Chapter 4: Static Timing Analysis — Part 1 (Q1 to Q50)

Timing Paths, Setup/Hold Equations, Slack, Clock Skew, and Jitter

1. STA Basics & The 4 Timing Paths

Q1 What is Static Timing Analysis (STA)?

Answer: STA is an exhaustive mathematical method of computing the expected timing of a digital circuit without requiring a simulation. It calculates delays along all possible paths and checks them against Setup and Hold requirements to ensure the circuit operates safely at the target frequency.

Q2 What is the difference between STA and DTA (Dynamic Timing Analysis)?

Answer:
• DTA (Simulation): Requires input test vectors. It only checks the paths exercised by the specific stimulus provided. It is slow but functionally accurate.
• STA: Does NOT require input vectors. It exhaustively analyzes 100% of the physical topological paths. It is extremely fast but ignores functional logic (it assumes all paths are sensitizable unless declared "false").

Q3 What defines the Startpoint and Endpoint of a valid Timing Path?

Answer:
• Startpoints: Input ports of the design, or the Clock pin of a Flip-Flop.
• Endpoints: Output ports of the design, or the Data (D) pin of a Flip-Flop.

Q4 Name the 4 fundamental Timing Paths analyzed in STA.

Answer:
1. In-to-Reg: Input Port $\rightarrow$ Flip-Flop (D pin).
2. Reg-to-Reg: Flip-Flop (CLK pin) $\rightarrow$ Flip-Flop (D pin). (The most common path)
3. Reg-to-Out: Flip-Flop (CLK pin) $\rightarrow$ Output Port.
4. In-to-Out (Combinational): Input Port $\rightarrow$ Output Port (no FFs in between).

The 4 Timing Paths
Q5 What is the "Launch Edge" and "Capture Edge"?

Answer:
• Launch Edge: The clock edge at the first Flip-Flop (FF1) that sends the data into the combinational logic.
• Capture Edge: The clock edge at the receiving Flip-Flop (FF2) that samples the data. For a standard single-cycle path, the Capture Edge is exactly one clock period ($T_{clk}$) after the Launch Edge.

Q6 Define the "Critical Path" in a design.

Answer: The critical path is the specific Reg-to-Reg logic path that possesses the maximum propagation delay (longest delay). It is the bottleneck of the chip. The delay of this single path dictates the absolute maximum clock frequency ($F_{max}$) the entire chip can run at.

Q7 What is a Data Path vs Clock Path?

Answer:
• Data Path: The route the data takes from the Clock pin of the Launch FF, out the Q pin, through combinational logic, to the D pin of the Capture FF.
• Clock Path: The route the clock signal takes from the primary Clock Port, through buffers (Clock Tree), to the Clock pin of a specific Flip-Flop.

Q8 What is $T_{cq}$ (Clock-to-Q delay)?

Answer: The time it takes for data to appear at the Q output pin of a Flip-Flop after the active edge of the clock arrives at the CLK pin. (It is a property of the Flip-Flop itself, not the combinational logic).

Q9 Tricky Is $T_{cq}$ a constant value for a specific Flip-Flop?

Answer: NO. $T_{cq}$ varies based on two physical factors:
1. Input Slew: How fast/slow the clock edge rises.
2. Output Load: The capacitance connected to the Q pin. (A heavily loaded Q pin increases $T_{cq}$). STA tools use Non-Linear Delay Models (NLDM) 2D lookup tables to find the exact $T_{cq}$.

Q10 What does it mean if a path is deemed a "False Path"?

Answer: A path that physically exists in the silicon netlist but can NEVER be functionally exercised, or a path whose timing does not matter (e.g., crossing asynchronous clock domains where synchronizers are used). Designers explicitly set these paths as "false" so the STA tool ignores them.

2. Setup and Hold Time Equations

Q11 Define Setup Time ($T_{su}$).

Answer: The minimum amount of time the data signal must remain stable at the D pin BEFORE the active clock edge arrives, to reliably be sampled without causing metastability.

Q12 Write the fundamental Setup Time Equation (Assuming zero clock skew).

To avoid a Setup Violation, the data must arrive at the Capture FF before the Capture clock edge occurs (minus the setup requirement).

$T_{cq} + T_{comb\_max} + T_{su} \le T_{clk}$

Where $T_{clk}$ is the clock period, $T_{cq}$ is clock-to-Q delay, and $T_{comb\_max}$ is the max combinational delay.

Q13 Define Hold Time ($T_h$).

Answer: The minimum amount of time the data signal must remain stable at the D pin AFTER the active clock edge arrives, to prevent the new incoming data from overwriting the current data being sampled.

Q14 Write the fundamental Hold Time Equation (Assuming zero clock skew).

To avoid a Hold Violation, the new data launched by the current clock edge must take long enough to arrive so it doesn't corrupt the data currently being captured.

$T_{cq} + T_{comb\_min} \ge T_h$
Q15 Whiteboard Why is the clock period ($T_{clk}$) NOT in the Hold Time equation?

Answer: Because Hold Time is a same-edge phenomenon. The data launched by edge #1 is checked against the capture of edge #1 at the destination flip-flop. Since both happen on the exact same clock edge, the period of the clock is completely irrelevant. You cannot fix a hold violation by slowing down the clock frequency!

Setup and Hold Timing Window
Q16 What does $T_{comb\_max}$ vs $T_{comb\_min}$ mean?

Answer: A block of combinational logic has multiple paths through it.
• $T_{comb\_max}$: The longest, slowest path through the logic cloud. Checked against Setup Time.
• $T_{comb\_min}$: The shortest, fastest path through the logic cloud. Checked against Hold Time.

Q17 Define "Setup Slack". Write the equation.

Answer: Setup Slack is the margin of safety for the setup time. It is the Required Time minus the Arrival Time.
Equation:

$Slack_{setup} = (T_{clk} - T_{su}) - (T_{cq} + T_{comb\_max})$

If Slack is POSITIVE, the path passes. If NEGATIVE, the path fails (timing violation).

Q18 Define "Hold Slack". Write the equation.

Answer: Hold Slack is the margin of safety for the hold time. It is the Arrival Time minus the Required Time.
Equation:

$Slack_{hold} = (T_{cq} + T_{comb\_min}) - T_h$

If POSITIVE, data arrives safely after the hold window closes. If NEGATIVE, data arrives too fast and overwrites early.

Q19 Tricky Can $T_h$ (Hold Time requirement of a FF) be negative?

Answer: Yes. A negative hold time means the data is allowed to change before the clock edge arrives at the external pin. This happens if the internal clock path inside the flip-flop cell has a longer delay than the internal data path.

Concept: If $T_h$ is negative (e.g., -0.2ns), it actually makes the Hold Equation easier to satisfy! The hold equation becomes $T_{cq} + T_{comb} \ge -0.2$, giving you extra margin.
Q20 Tricky Can $T_{su}$ (Setup Time requirement) be negative?

Answer: Yes. If the internal data path inside the flip-flop is much slower than the internal clock path, the data can arrive at the external D-pin after the external clock edge has triggered, and still get caught by the internal master latch.

3. Clock Skew and Its Impact

Q21 What is Clock Skew?

Answer: Clock Skew is the difference in arrival time of the clock edge at the Launch Flip-Flop vs the Capture Flip-Flop, caused by unequal wire routing lengths and buffer delays in the Clock Tree.

Q22 Define Positive Skew.

Answer: Positive Skew occurs when the clock edge arrives at the Capture FF LATER than the Launch FF. ($T_{capture} > T_{launch}$). The clock is delayed going to the destination.

Q23 Define Negative Skew.

Answer: Negative Skew occurs when the clock edge arrives at the Capture FF EARLIER than the Launch FF. ($T_{capture} < T_{launch}$). The clock is delayed going to the source.

Q24 How does Positive Skew affect Setup and Hold time?

Answer:
• Setup: HELPS Setup time. The capture edge is delayed, giving the data more time to travel.
• Hold: HURTS Hold time. The capture edge is delayed, meaning the hold window stays open longer, increasing the risk of the next data crashing into it.

Q25 How does Negative Skew affect Setup and Hold time?

Answer:
• Setup: HURTS Setup time. The capture edge arrives early, giving the data less time to arrive.
• Hold: HELPS Hold time. The capture edge arrives early, closing the hold window sooner, protecting it from fast data.

Positive vs Negative Clock Skew
Q26 Write the Setup Time equation INCLUDING Clock Skew.

Let $T_{skew} = T_{capture\_delay} - T_{launch\_delay}$.

$T_{cq} + T_{comb\_max} \le T_{clk} + T_{skew} - T_{su}$
Q27 Write the Hold Time equation INCLUDING Clock Skew.
$T_{cq} + T_{comb\_min} \ge T_{h} + T_{skew}$

If $T_{skew}$ is positive, the right side becomes larger, making it harder to satisfy the Hold equation.

Q28 What is "Useful Skew"?

Answer: It is an advanced Physical Design technique. If a critical path is failing Setup by 100ps, the tool intentionally adds 100ps of delay buffers to the clock line of the Capture FF (creating positive skew). This "borrows time" from the next clock cycle to fix the setup violation.

Q29 What is the danger of using Useful Skew?

Answer: You rob Peter to pay Paul. By delaying the clock to FF2 to help the path from FF1 $\rightarrow$ FF2, you are causing Negative Skew for the next path from FF2 $\rightarrow$ FF3. The tool must verify that FF3 has enough setup margin to absorb the penalty.

Q30 What is Local Skew vs Global Skew?

Answer:
• Local Skew: The difference in clock arrival times between two directly communicating flip-flops. (This is all that matters for STA equations).
• Global Skew: The difference in clock arrival times between the earliest and latest flip-flops across the entire chip.

4. Clock Jitter & Uncertainty

Q31 What is Clock Jitter?

Answer: Jitter is the random, temporal variation of the clock edge from its ideal perfectly periodic position. Unlike skew (which is a static spatial delay), jitter changes constantly over time due to thermal noise in the PLL, power supply ripples, and crosstalk.

Q32 What is Period Jitter?

Answer: The variation in the duration of any single clock period compared to the ideal period. E.g., if ideal $T_{clk} = 10ns$, period jitter might cause cycle 1 to be $9.9ns$, cycle 2 to be $10.1ns$.

Q33 What is Cycle-to-Cycle Jitter?

Answer: The change in duration between two adjacent clock cycles. E.g., Cycle 1 is $10.1ns$, Cycle 2 is $9.9ns$. The cycle-to-cycle jitter is $0.2ns$.

Q34 How does Jitter affect the Setup equation?

Answer: Setup is checked between two different edges (Launch on edge $n$, Capture on edge $n+1$). Since the time between these edges can shrink due to jitter, it hurts Setup time. We subtract it from the available period.

$T_{cq} + T_{comb} \le T_{clk} - T_{jitter} - T_{su}$

Q35 Tricky How does Jitter affect the Hold equation?

Answer: It doesn't! Hold time is checked on the exact same clock edge (Launch on edge $n$, Capture on edge $n$). Because the clock edge can only arrive at one instant in time for that specific cycle, jitter does not shrink the hold window. Jitter = 0 for hold calculations.

Q36 What is Clock Uncertainty?

Answer: It is a pessimistic margin added by the designer to account for all unknown variations in the clock tree before the layout is actually finished.
Uncertainty = Skew (estimated) + Jitter + Design Margin.

5. STA Basic Numericals & Fixes

Q37 Numerical A circuit has $T_{cq} = 2ns$, $T_{su} = 1ns$, $T_h = 0.5ns$, $T_{comb} = 4ns$. What is the Maximum Clock Frequency ($F_{max}$) assuming zero skew/jitter?

Answer:
Setup Equation: $T_{clk} \ge T_{cq} + T_{comb} + T_{su}$
$T_{clk} \ge 2 + 4 + 1 = 7ns$
$F_{max} = \frac{1}{T_{clk}} = \frac{1}{7 \times 10^{-9}} \approx 142.8 \text{ MHz}$.

Q38 Numerical In the previous circuit, check if there is a Hold violation.

Answer:
Hold Equation: $T_{cq} + T_{comb\_min} \ge T_h$
$2ns + 4ns = 6ns$.
Is $6ns \ge 0.5ns$? Yes.
No Hold violation. (Hold Slack = $+5.5ns$).

Q39 Numerical The clock routing to the Capture FF is longer than to the Launch FF, creating $+1.5ns$ of Skew. What is the new $F_{max}$?

Answer: Positive skew HELPS setup time.
$T_{clk} \ge T_{cq} + T_{comb} + T_{su} - T_{skew}$
$T_{clk} \ge 2 + 4 + 1 - 1.5 = 5.5ns$
$F_{max} = \frac{1}{5.5ns} \approx 181.8 \text{ MHz}$. (The circuit got faster!)

Q40 Numerical With that $+1.5ns$ skew, check the Hold time again.

Answer: Positive skew HURTS hold time.
$T_{cq} + T_{comb\_min} \ge T_h + T_{skew}$
$2 + 4 \ge 0.5 + 1.5$
$6ns \ge 2ns$. Yes. Still no hold violation. (Hold Slack dropped from 5.5ns to 4.0ns).

Q41 How do you fix a Setup Violation in the RTL (Front-end)?

Answer:
1. Pipeline: Insert a Flip-Flop in the middle of the combinational logic cloud to cut the $T_{comb}$ in half.
2. Logic Restructuring: Move late-arriving signals closer to the end of the logic chain (e.g., closer to the MUX output).
3. Parallelism: Compute data in parallel rather than serially.

Q42 How do you fix a Setup Violation in Physical Design (Back-end)?

Answer:
1. Swap the slow combinational gates with Low-Vt (LVT) faster cells.
2. Upsize the driving gates to drive the RC load faster.
3. Use Useful Skew (delay the clock to the capture FF).
4. Move the logic cells closer together to reduce routing RC delay.

Q43 How do you fix a Hold Violation?

Answer: The data is arriving too fast. You must slow it down.
Solution: Insert Delay Buffers in the combinational data path to artificially increase $T_{comb\_min}$. (Never decrease the clock frequency; it won't help!).

Q44 Which is fixed first during the ASIC flow: Setup or Hold?

Answer: Setup is fixed first. Setup violations can be fixed by lowering the clock frequency if absolutely necessary, or pipelining in RTL. Hold violations are fixed at the very end (Post-Route) by inserting buffers. If you insert hold buffers too early, they take up area and might create setup violations later.

Q45 Why is a Hold Violation considered fatal?

Answer: A Setup violation can be "patched" in silicon by simply lowering the clock frequency until the chip passes. A Hold violation is independent of the clock period. If silicon comes back with a hold violation, the chip is dead on arrival at any frequency. It must be thrown away.

Q46 What is a Multi-Cycle Path (MCP)?

Answer: A path where the combinational logic is so deep it requires more than 1 clock cycle to evaluate (e.g., a complex multiplier). The designer explicitly tells the STA tool (e.g., `set_multicycle_path 2`) to allow the data to take 2 clock cycles before the Capture FF samples it.

Q47 Tricky If you set a Setup Multi-Cycle Path to 2, what happens to the Hold check by default?

Answer: By default, STA tools move the Hold check to 1 cycle before the Setup capture edge. So if Setup is checked at edge 2, Hold is checked at edge 1. This means the data must hold for an entire clock cycle, which usually causes massive hold violations! You must explicitly add a `set_multicycle_path -hold 1` to move the hold check back to edge 0.

Q48 What is Half-Cycle Timing?

Answer: When data is launched on the rising edge of a clock and captured on the falling edge of the same clock. The available time for $T_{comb}$ is chopped in half ($T_{clk}/2$). It makes setup time incredibly tight.

Q49 Why does routing delay (wire RC) affect Setup time more than Hold time?

Answer: Setup time is governed by the maximum (slowest) path. Long wires add RC delay, pushing $T_{comb\_max}$ higher, causing setup failures. Hold time is governed by the minimum (fastest) path. If two FFs are placed directly next to each other (0 wire delay), $T_{comb\_min}$ is tiny, causing a hold failure.

Q50 The Golden Rule of STA: How do you remember the equations under pressure?

Answer:
• Setup: Data must be FAST ENOUGH to beat the clock. (Data Arrival < Clock Arrival).
• Hold: Data must be SLOW ENOUGH to not crash into the current clock. (Data Arrival > Hold Requirement).

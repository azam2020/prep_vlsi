Chapter 2: Verilog HDL — Part 3 (Q101 to Q150)

Tasks vs Functions, FSM Coding Architectures, Parameterization & Advanced RTL

8. Tasks vs. Functions

Q101 What is the fundamental difference between a Task and a Function regarding execution time?

Answer: A Function must execute in zero simulation time. It cannot contain any timing delays (`#10`), event controls (`@(posedge clk)`), or wait statements. A Task can consume simulation time and can contain delays and clock edge triggers.

Q102 Can a Function call a Task? Can a Task call a Function?

Answer:
• A Task CAN call a Function.
• A Function CANNOT call a Task (because calling a task might violate the function's strict zero-time execution rule).

Q103 How many outputs can a Function return compared to a Task?

Answer: A Function returns exactly ONE value through its name (like a mathematical function). It must have at least one input. A Task does not return a value by its name; instead, it can have ZERO or MULTIPLE outputs driven via its `output` or `inout` port arguments.

Q104 Are Tasks and Functions synthesizable?

Answer:
• Functions: Always synthesizable, provided they contain standard combinational logic without simulation-only system calls. They synthesize into combinational logic blocks.
• Tasks: Synthesizable ONLY IF they do not contain timing delays (`#`) or event controls (`@`). If a task contains delays, it is strictly for testbench simulation.

Q105 Tricky What does the automatic keyword do in Verilog Tasks/Functions?

Answer: By default, all variables inside a Verilog task/function are static (shared across all calls). If Task A is called concurrently from two different `always` blocks, they will overwrite each other's variables! Adding automatic (e.g., `task automatic my_task;`) forces the simulator to allocate dynamically instanced memory on the stack for each call, making it safe for concurrent or recursive execution.

Q106 Can you write a recursive function in Verilog?

Answer: Yes, but only if the function is declared as automatic. A static function cannot be recursive because it only has one memory space for its variables.

Q107 Where are non-synthesizable tasks predominantly used in the industry?

Answer: In Testbenches (Verification). Verification engineers use tasks heavily to create reusable Bus Functional Models (BFMs), such as task write_ahb(addr, data);, which toggles the specific clock-cycle-level signaling required to simulate a bus transaction.

Q108 Can a Task have inout ports? Can a Function have inout ports?

Answer: A Task can have `input`, `output`, and `inout` ports. A Function must have at least one `input` port, but it cannot have `output` or `inout` ports in standard Verilog (SystemVerilog relaxes this, but standard Verilog forbids it).

Q109 Can you drive a global module-level reg from inside a Task?

Answer: Yes. Tasks and functions have visibility into the module scope they are declared in. They can read and write to global `reg` variables without needing to pass them explicitly through ports.

Q110 How are arguments passed to Tasks in Verilog: Pass by Value or Pass by Reference?

Answer: Verilog strictly uses Pass by Value. When a task is called, the inputs are copied into the task's local variables. When the task finishes, its outputs are copied back out to the caller. (SystemVerilog introduces `ref` for pass by reference).

Q111 True or False: Functions can contain non-blocking assignments (`<=`).

Answer: False. Functions are strictly meant to model combinational behavior (zero-time). They must only use blocking assignments (`=`). Using `<=`, which defers assignment to the NBA region, violates zero-time completion.

Q112 Write the syntax for declaring and calling a basic function that adds two 8-bit numbers.
function [8:0] add_nums;
    input [7:0] a, b;
    begin
        add_nums = a + b; // Assign to the function's name to return
    end
endfunction

// Calling it:
wire [8:0] sum = add_nums(x, y);
Q113 What is a constant function?

Answer: A function whose arguments are all compile-time constants (e.g., parameters). The Verilog compiler executes the function during compilation/elaboration, not during runtime, and replaces the call with the calculated constant value. Commonly used to calculate parameter widths (like `$clog2`).

Q114 Can you declare a Task outside of a module?

Answer: In standard Verilog-2001, NO. Tasks and Functions must be declared inside a `module`. (SystemVerilog allows declaring them in `packages` or `interfaces`).

Q115 Tricky What happens if you call a task in a continuous assignment? (e.g., assign out = my_task(in);)

Answer: It will trigger a compilation error! Tasks do not return a value to the expression they are called from, and they cannot be used in continuous `assign` statements. Only Functions can be called in continuous assignments.

9. FSM Coding Architectures (Moore/Mealy)

Q116 What is the industry standard coding architecture for FSMs in Verilog?

Answer: The 3-Always Block architecture.

  1. Sequential Block: Updates current_state <= next_state.
  2. Combinational Block: Computes next_state based on inputs and current_state.
  3. Output Block: Computes outputs (can be combinational or registered).
Q117 Why is a 1-Always Block FSM (putting state updates and next-state logic in the same clocked block) heavily discouraged?

Answer: It leads to spaghetti code that is extremely hard to debug, makes registering outputs difficult, and often causes the logic to become dependent on the clock cycle routing rather than the pure state machine logic. It mixes memory abstraction with logic abstraction.

Q118 How do you define FSM states securely in Verilog?

Answer: Using localparam. 

localparam IDLE = 2'b00, 
           READ = 2'b01, 
           WRITE = 2'b10;

Concept: Never use `define for states because macros are global and will conflict with other modules that also have an "IDLE" state. Never use parameter because states should not be overridable during instantiation. localparam provides safe, local, immutable constants.
Q119 Tricky What is the fatal flaw with a pure Mealy Machine output, and how do we fix it in RTL?

Answer: A pure Mealy output depends directly on combinational inputs. If the external inputs glitch (bounce between 0 and 1) between clock edges, those glitches will immediately propagate straight through the FSM to the outputs, corrupting downstream logic.

Fix: We use a Registered Mealy Output (syncing the combinational output to a Flip-Flop before it leaves the module) to absorb the glitches, though this delays the output by one clock cycle.

Q120 Write the sequential State Update block for a 3-block FSM.
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        current_state <= IDLE;
    else
        current_state <= next_state;
end
Q121 In the next-state logic block, why MUST you use blocking assignments (=)?

Answer: The next-state block is purely combinational (always @(*)). Per the Golden Rule of Verilog, combinational logic must use blocking assignments to evaluate instantly without incurring delta-cycle delays in simulation.

Q122 What happens if you forget the default: next_state = IDLE; clause in your FSM next-state case statement?

Answer: The synthesis tool will infer a Level-Sensitive Latch. The FSM will freeze/lock up in simulation under unmapped conditions, and the silicon will fail static timing analysis.

Q123 Reverse Engineering: You look at an FSM's output block. It is written as always @(*) begin out = (current_state == READ) && (in_ready == 1); end. Is this Moore or Mealy?

Answer: Mealy. The output depends on the `current_state` AND a current input signal (`in_ready`). If it only depended on `current_state`, it would be a Moore machine.

Q124 What is "State Explosion" in FSM design?

Answer: State explosion occurs when you try to design a single, massive FSM to control multiple independent processes. The number of states multiplies exponentially (e.g., Process A has 4 states, Process B has 5 states → Combined FSM requires 20 states). The solution is to use communicating, hierarchical FSMs.

Q125 Tricky What does the synthesis attribute /* synopsys safe_fsm */ do?

Answer: In hostile environments (e.g., space radiation), an SEU (Single Event Upset) might flip a flip-flop bit, pushing the FSM into an invalid, undefined state that isn't in your code. Normally, the FSM would hang forever. safe_fsm forces the synthesis tool to build recovery logic that automatically forces the FSM back to the reset/IDLE state if an illegal state vector is detected.

Q126 How does One-Hot encoding optimize the next-state combinational logic?

Answer: In One-Hot, only one bit is High per state. The next-state logic equation for any state simplifies to just checking the 1-bit status of the preceding states. It completely eliminates the need for wide, deep decoding logic (no multi-bit comparators needed), allowing the FSM to run at much higher clock frequencies.

Q127 Why use Gray Code encoding for FSMs crossing clock domains?

Answer: In Gray code, only 1 bit transitions between adjacent states. If an asynchronous clock samples the state during a transition, it will either read the old state perfectly or the new state perfectly. It will never read a garbage intermediate state. (If transitioning from 01 to 10 in binary, sampling during the transition could incorrectly yield 00 or 11).

Q128 Should FSM outputs be registered? Why?

Answer: Yes, registering outputs (syncing them to a Flip-Flop) is a best practice. It eliminates glitches, provides clean timing for the receiving block (full clock cycle available for setup time), and isolates internal FSM combinational delays from downstream modules.

Q129 What is the output delay of a Moore Machine compared to the state change?

Answer: A pure combinational Moore output changes immediately after the clock edge updates the state. However, because it relies on the state changing, it inherently lags the input that caused the state change by one full clock cycle.

Q130 How do you force a synthesis tool to use One-Hot encoding if you wrote your states in binary?

Answer: You pass an attribute or pragma to the compiler directly in the RTL. 

(* fsm_encoding = "one_hot" *) reg [2:0] state;
Modern synthesis tools generally ignore your specific localparam values anyway and re-encode FSMs automatically based on area/speed optimization algorithms unless explicitly instructed not to.

10. Parameterization & Advanced Concepts

Q131 What are the two ways to override a parameter during module instantiation? Which is preferred?

Answer:
1. Positional: my_mod #(8, 4) u1 (clk, in, out);
2. Named (Preferred): my_mod #(.WIDTH(8), .DEPTH(4)) u1 (clk, in, out);
Named override is the industry standard because it prevents fatal mapping errors if the parameter order changes in the sub-module.

Q132 What is defparam, and why is it deprecated?

Answer: defparam allows overriding a parameter from anywhere in the testbench using hierarchical paths (e.g., defparam top.u1.my_mod.WIDTH = 16;). It is deprecated (banned in modern RTL) because it destroys modularity and makes the code impossible for synthesis tools to compile predictably in a bottom-up flow.

Q133 Tricky Can a localparam be overridden during instantiation?

Answer: NO. That is the entire purpose of localparam. It protects internal constants (like FSM state encodings or calculated bus widths) from being accidentally altered by a higher-level module.

Q134 How do you parameterize a module such that the address width automatically adjusts based on the Memory Depth parameter?
module memory #(parameter DEPTH = 256) (
    // Automatically calculate address width
    input [$clog2(DEPTH)-1:0] addr, 
    ...
);
Q135 How do you initialize a Memory/ROM array from a text file in Verilog?

Answer: Using system tasks $readmemb (for binary files) or $readmemh (for hex files). These are executed inside an initial block.

reg [7:0] rom [0:255];
initial begin
    $readmemh("rom_data.hex", rom);
end
Q136 Is $readmemh synthesizable?

Answer: For ASICs, generally No. ASIC ROMs are hard-coded physically. For FPGAs, YES! FPGA synthesis tools (Vivado/Quartus) will synthesize $readmemh inside an initial block and bake the hex file directly into the bitstream to initialize BRAM blocks.

Q137 Can a genvar variable be read during normal simulation time (e.g., inside an always @(posedge clk) block)?

Answer: NO. A genvar exists exclusively during the compilation/elaboration phase to unroll loops and instantiate hardware. Once the design is compiled, the genvar ceases to exist. It has no physical hardware representation.

Q138 Write the syntax for declaring a multi-dimensional array (e.g., a 3D array: 4 arrays, each holding 16 words, each 8-bits wide).

Answer: 

reg [7:0] memory_3d [0:3][0:15];
Rule: Packed dimensions (bit-width) go before the name. Unpacked dimensions (depth/arrays) go after the name, ordered left-to-right.

Q139 Explain the scope difference between `define and parameter.

Answer:
• `define: Lexical scope. Once defined, it remains active across ALL subsequently compiled files until a `undef is encountered. It pollutes the global namespace.
• parameter: Module scope. It exists only within the endmodule boundary of the module it is declared in.

Q140 Can a Verilog parameter hold a String?

Answer: Yes. Strings in standard Verilog are just arrays of 8-bit ASCII characters. 

parameter FSM_NAME = "MAIN_CTRL";
This is heavily used in testbenches for logging dynamic messages.

Q141 What does the compiler directive `timescale 1ns / 1ps mean?

Answer: It defines simulation time units and precision.
• 1ns (Reference Time Unit): If you write #5, the simulator delays for 5 ns.
• 1ps (Precision): The simulator rounds all delay fractions to the nearest picosecond. (e.g., #1.0005 becomes #1.001 ns).

Q142 What happens if Module A has `timescale 1ns/1ps and Module B has `timescale 1us/1ns, and they are compiled together?

Answer: The simulator will use the local timescale for each module when calculating delays, BUT the overall simulation global precision drops to the smallest precision defined anywhere in the design (1ps in this case). This can cause massive simulation slowdowns.

Q143 What is a Verilog Attribute? Give an example.

Answer: Attributes pass specific instructions to the synthesis or simulation tool without changing the RTL logic. They are wrapped in (* *).
Example: (* keep = "true" *) wire debug_sig; (Tells synthesis NOT to delete this wire even if it appears to be dead logic).

Q144 Can a Verilog module have zero ports?

Answer: Yes. module tb_top; ... endmodule. This is exactly how Top-Level Testbenches are defined. They have no physical I/O to the outside world; they generate clocks and stimulus internally.

Q145 Tricky What does a = b << c; do if `c` is unknown (`X`)?

Answer: If the shift amount is unknown (`X` or `Z`), the entire result `a` becomes X. The simulator cannot guess how many places to shift.

Q146 What is an Implicit Wire declaration, and how does it cause bugs?

Answer: If you connect a signal to a module instantiation port but forget to declare that signal, Verilog automatically creates an implicit 1-bit wire. If the actual port was 32-bits wide, 31 bits get silently truncated/disconnected. Fix: Use `default_nettype none.

Q147 How do you force a combinational loop to break during simulation (e.g., to model a ring oscillator in a testbench)?

Answer: You must insert a small delay. assign #1 inv_out = ~inv_out;. Without the `#1`, the simulator will evaluate the loop infinitely at time 0 (delta cycle infinite loop) and freeze.

Q148 Can you initialize a `reg` at declaration? (e.g., reg a = 1'b1;). Is it synthesizable?

Answer: Yes, you can. For ASICs, this is generally IGNORED by synthesis tools (they require a physical reset pin). For FPGAs, this is highly recommended and perfectly synthesizable to set the power-on SRAM bit state.

Q149 What does assign (strong1, weak0) y = a; mean?

Answer: It defines Drive Strength. It tells the simulator that if `a` is 1, it pulls the wire with strong (VDD) force. If `a` is 0, it pulls with weak (pull-down resistor) force. This is heavily used to model I/O pads and I2C open-drain pull-ups in gate-level simulations.

Q150 The Final Test You have a parameter W = 8. You write assign out = -1; where out is W bits wide. What is the value of out in binary?

Answer: 8'b1111_1111.

Concept: -1 in 2's complement is all 1s. Verilog evaluates the -1, sees the LHS is 8-bits wide, and safely sign-extends the all-1s pattern across the entire 8-bit bus.

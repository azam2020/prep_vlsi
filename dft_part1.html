Chapter 7: Design for Testability (DFT)

Fault Models, Scan Chains, ATPG, BIST, and JTAG Boundary Scan

1. DFT Basics & Fault Models

Q1 What is Design for Testability (DFT)?

Answer: DFT is the practice of adding specialized hardware features to an IC design to make it easier to test the manufactured silicon for physical defects. It bridges the gap between perfectly simulated RTL and the reality of dirty manufacturing processes (dust, over-etching, misalignment) that cause physical shorts or opens.

Q2 What is the difference between Functional Verification and Silicon Testing (DFT)?

Answer:
• Verification (Pre-Silicon): Ensures the RTL logic does what the specification says. It finds design bugs.
• DFT (Post-Silicon): Assumes the logic is perfect. It checks if the physical chip was manufactured correctly. It finds manufacturing defects.

Q3 What are the two fundamental pillars of Testability?

Answer:
1. Controllability: The ability to set a specific internal node to a desired logic state (0 or 1) from the external input pins.
2. Observability: The ability to observe the logical state of a specific internal node at the external output pins.

Q4 What is the Stuck-at Fault (SAF) model?

Answer: A logical fault model that assumes a manufacturing defect causes a specific wire/node in the circuit to be permanently tied to VDD (Stuck-at-1 / SA1) or permanently tied to GND (Stuck-at-0 / SA0), regardless of the signals driving it.

Q5 How do you test for a Stuck-at-0 fault on a wire?

Answer: You must Control the wire to a Logic 1 (using input stimulus), and then Observe the wire at an output. If the output shows the behavior of a Logic 1, the wire is healthy. If the output shows the behavior of a Logic 0, the wire is Stuck-at-0.

Q6 What is Fault Equivalence (Fault Collapsing)?

Answer: Many faults produce the exact same erroneous output, making them indistinguishable. For example, a Stuck-at-0 on the input of an AND gate produces the exact same output (0) as a Stuck-at-0 on the output of the AND gate. Fault collapsing groups these equivalent faults together, so ATPG only needs to generate one test pattern for the whole group, drastically reducing test time.

Q7 What is the Transition Delay Fault (TDF) model?

Answer: While SAF checks if a wire can toggle at all, TDF checks if it can toggle fast enough. It detects slow-to-rise and slow-to-fall defects caused by partial resistive shorts or vias with excessive resistance. It requires two test patterns (Launch and Capture) run at the target clock speed (At-Speed Testing).

2. Scan Chain Architecture

Q8 What is a Scan Chain, and why do we need it?

Answer: Deep inside a chip, there are flip-flops buried behind 100 levels of logic, making them impossible to control or observe from the I/O pins. A Scan Chain converts every standard flip-flop into a Shift Register. During test mode, test equipment shifts data directly into every flip-flop serially, bypassing the combinational logic entirely.

Q9 How is a standard D-Flip-Flop converted into a Scan Flip-Flop (SFF)?

Answer: A 2:1 Multiplexer is physically added to the D-input of the flip-flop.
• D (Data): The normal functional data pin.
• SI (Scan In): The test data pin coming from the previous flip-flop in the chain.
• SE (Scan Enable): The select line that toggles between Functional Mode and Shift Mode.

Scan Flip-Flop (SFF) Architecture
Q10 Explain the Shift Mode vs. Capture Mode process in Scan Testing.

Answer:
1. Shift Mode (SE = 1): The MUX connects SI. The tester clocks the chip repeatedly to serially shift the test pattern into all flip-flops like a giant shift register.
2. Capture Mode (SE = 0): The MUX connects functional D. The tester pulses the clock exactly once. The flip-flops capture the combinatorial logic response to the test pattern.
3. Shift Out (SE = 1): The captured responses are serially shifted out through the SO pin while the next test pattern is shifted in.

Q11 What is the timing and area penalty of adding Scan Chains?

Answer:
• Area: Increases by ~5-10% because every flip-flop gets a MUX, increasing silicon footprint.
• Timing: The MUX sits directly in the data path, adding a gate delay to every single Reg-to-Reg path, slightly degrading the maximum clock frequency (Setup penalty).

Q12 Why are Hold Time violations the biggest nightmare in Scan Chains?

Answer: In Shift Mode, the Q pin of FF1 connects directly to the SI pin of FF2. There is almost zero combinational logic (zero delay) between them. If there is even a tiny bit of clock skew between FF1 and FF2, FF2 will suffer a catastrophic hold violation and capture the wrong shift bit, breaking the entire scan chain.

Q13 Tricky How are Hold violations fixed in a Scan Chain?

Answer: Since scan paths are not critical for setup time (shifting is done at very low frequencies, e.g., 10-50 MHz), the physical design tool aggressively inserts Delay Buffers between the SO pin of one flop and the SI pin of the next, artificially inflating the path delay to guarantee hold time safety.

Q14 What is a Lockup Latch, and when is it used in Scan Chains?

Answer: A negative-level sensitive latch placed between two scan flip-flops that reside in different clock domains (or different branches of a highly skewed clock tree). It delays the shift data by a half-cycle, guaranteeing immense hold-time margin across the domain crossing.

Q15 What is Scan Chain Reordering?

Answer: During synthesis, the tool stitches the scan chain alphabetically based on RTL names, resulting in scan wires crisscrossing the chip randomly. During Placement, the tool disconnects the chain and re-stitches it based purely on physical proximity, connecting neighbors to neighbors to drastically reduce routing congestion.

3. ATPG (Automatic Test Pattern Generation)

Q16 What is ATPG?

Answer: Automatic Test Pattern Generation. It is an EDA software algorithm that analyzes the gate-level netlist and mathematically calculates the exact 1s and 0s (test vectors) required to be shifted into the scan chain to excite and observe every possible fault in the design.

Q17 What is Fault Coverage vs. Test Coverage?

Answer:
• Fault Coverage: (Detected Faults / Total Faults). Includes untestable faults in the denominator.
• Test Coverage: (Detected Faults / Total Testable Faults). This is the metric engineers care about. Target is usually >99%.

Q18 What causes a fault to be "Untestable"?

Answer: Redundant logic, floating inputs, or logic explicitly tied to VDD/GND (like Tie cells). If a node is permanently tied to 1, a Stuck-at-1 fault is impossible to detect because the node behaves exactly as intended.

Q19 Tricky What is At-Speed Testing, and why is it necessary?

Answer: Legacy SAF tests are run at very slow shift frequencies (e.g., 20MHz). A wire might pass SAF at 20MHz, but due to a highly resistive via defect, it fails at the functional speed of 1GHz (Transition Delay Fault). At-Speed Testing uses the PLL to fire the Capture clock pulses at the true functional 1GHz frequency to catch these resistive defects.

Q20 Explain LOC (Launch-Off-Capture) vs LOS (Launch-Off-Shift) in At-Speed testing.

Answer: Two methods for testing Transition Delay Faults:
• LOS: The transition is launched by the last Shift clock edge, and captured by a fast Capture edge. (Requires SE to toggle extremely fast, which is hard to route).
• LOC (Broadside): Shift completes. SE goes low. The PLL fires TWO fast Capture pulses. The first pulse launches the transition, the second pulse captures it. (Industry standard because SE doesn't need to be timing-critical).

Q21 What is IDDQ Testing?

Answer: It measures the Quiescent Power Supply Current ($I_{DDQ}$). In perfect CMOS, static current is extremely low. The tester halts the clock and measures the DC current. If there is a bridging fault (short circuit) or a damaged gate oxide, the quiescent current will be anomalously high, instantly flagging a defective chip.

Q22 Why is IDDQ testing becoming obsolete in sub-10nm nodes?

Answer: Background subthreshold leakage current is so massively high in deep sub-micron nodes that the tiny extra leakage caused by a defect is completely masked by the background noise. It is impossible to distinguish a healthy leaky chip from a defective chip.

Q23 What is Test Compression?

Answer: A chip with 1 million flip-flops needs 1 million cycles just to shift in one test pattern. This takes too long on expensive ATE (Automated Test Equipment). Compression uses a decompressor on-chip to take a few pins of compressed data from the tester, expand it into thousands of short internal scan chains, and compress the output signatures, cutting test time by 100x.

Q24 What are "X-states" in ATPG, and why are they dangerous?

Answer: Unknown states caused by uninitialized memory, analog blocks, or asynchronous resets during test mode. If an X-state propagates into the scan chain, it corrupts the expected output signature, causing the tester to fail a perfectly good chip. DFT engineers use X-bounding (blocking X's with AND/OR gates) to isolate them.

Q25 What does a Silicon Tester (ATE) actually do on the factory floor?

Answer: The ATE (Automated Test Equipment) is a million-dollar machine with mechanical probes. It touches the chip's pads, applies power, controls the Scan Enable, pumps the ATPG 1s and 0s into the Scan In pins, reads the Scan Out pins, and compares the output against a golden file to bin the chip as Pass or Fail.

4. Memory & Logic BIST

Q26 What is BIST (Built-In Self-Test)?

Answer: BIST places the testing logic (pattern generator and output comparator) directly inside the silicon chip. Instead of an external $1M tester pumping bits, the chip tests itself at full functional speed and simply outputs a 1-bit Pass/Fail signal.

Q27 Why do we use MBIST (Memory BIST) specifically for SRAMs?

Answer: SRAMs are insanely dense and make up 50-70% of an SoC's area. They cannot be put on a scan chain. MBIST is a dedicated hardware controller placed next to the SRAM that bombards it with specific algorithmic read/write patterns at full CPU speed to find cell defects.

Q28 What are the typical faults found in Memories?

Answer:
• Stuck-at Faults: A memory cell is stuck at 0 or 1.
• Coupling Faults: Writing a 1 to Cell A accidentally flips Cell B.
• Address Decoder Faults: Writing to Address 0 accidentally writes to Address 4.

Q29 What is a March Algorithm in MBIST?

Answer: A sequence of operations applied to every cell in the memory array, marching from Address 0 to N, and then from N back to 0. It uses operations like: Write 0, Read 0, Write 1, Read 1.

Q30 Tricky Why is the "March C-" algorithm the industry standard?

Answer: Because of its mathematical efficiency. With a complexity of $O(10N)$ (10 operations per memory word), March C- is mathematically proven to detect 100% of stuck-at faults, 100% of address decoder faults, and 100% of unlinked coupling faults. It provides maximum coverage in minimal test time.

Q31 What is Memory Repair (BISR - Built-In Self-Repair)?

Answer: SRAM blocks are fabricated with extra "redundant" rows and columns. If MBIST detects a defective cell, BISR uses eFuses (blowable fuses) to permanently remap the address decoder, bypassing the broken row and substituting a redundant row. This saves chips that would otherwise be thrown away, massively increasing manufacturing yield.

Q32 What is Logic BIST (LBIST)?

Answer: While MBIST tests memory, LBIST tests the standard combinational logic. It generates pseudo-random test patterns internally, feeds them into the scan chains, and compresses the outputs into a signature. It is heavily used in Automotive chips (ISO 26262) so the car can test its own brakes/steering chip every time you start the engine.

Q33 What is an LFSR (Linear Feedback Shift Register), and why is it used in LBIST?

Answer: An LFSR is a shift register with XOR gates on specific feedback taps. It generates pseudo-random sequences of 1s and 0s. In LBIST, it is used as a PRPG (Pseudo-Random Pattern Generator) to blast random stimulus into the scan chains cheaply and quickly.

Q34 What is a MISR (Multiple Input Signature Register)?

Answer: A component used at the output of LBIST. Instead of checking millions of output bits one-by-one, a MISR mathematically compresses all the captured scan chain outputs into a single, compact 32-bit or 64-bit Hex code called a Signature. If the chip is healthy, it outputs the golden signature (e.g., `0xDEADBEEF`). If defective, the signature alters.

Q35 What is "Aliasing" in a MISR?

Answer: Aliasing is the mathematically rare event where a defective chip produces the exact same golden signature as a healthy chip due to the lossy nature of compression. A 32-bit MISR has an aliasing probability of $2^{-32}$, which is so low it is deemed acceptable.

Q36 Contrast ATPG and LBIST.

Answer:
• ATPG: Deterministic. Calculates the exact minimal patterns needed. Achieves ~99.9% coverage. Requires external ATE tester.
• LBIST: Random. Blasts millions of random patterns. Hard to hit hard-to-reach faults (only achieves ~90% coverage). Runs entirely independently on-chip.

Q37 What are "Test Points"?

Answer: Logic gates (AND/OR) manually inserted by DFT engineers deep inside the RTL to improve controllability or observability of stubborn logic nodes that random LBIST patterns cannot naturally excite.

Q38 What is Burn-In Testing?

Answer: Chips are placed in high-voltage, high-temperature ovens and run continuously for hours. This accelerates "infant mortality" defects (weak gate oxides or partial vias) causing them to fail in the factory rather than in the customer's hands 6 months later.

5. Boundary Scan & JTAG (IEEE 1149.1)

Q39 What is JTAG (Boundary Scan)?

Answer: Joint Test Action Group (IEEE 1149.1). It is an industry-standard serial interface designed to test the physical connectivity of chips mounted on a PCB. It allows testers to manipulate the I/O pins of a chip without physically probing them, solving the problem of testing densely packed BGA (Ball Grid Array) boards.

Q40 Name the 5 physical pins required for JTAG (The TAP Interface).

Answer: Test Access Port (TAP) pins:
1. TCK: Test Clock (independent of system clock).
2. TMS: Test Mode Select (controls the internal state machine).
3. TDI: Test Data In (serial data to chip).
4. TDO: Test Data Out (serial data from chip).
5. TRST: Test Reset (Optional, active low reset for TAP controller).

Q41 What is a Boundary Scan Cell (BSC)?

Answer: A specialized MUX/Flip-Flop circuit placed directly between the core logic and the physical I/O pad. During normal mode, signals pass through transparently. During JTAG test mode, the BSC intercepts the pin, allowing JTAG to drive a value onto the board or capture a value from the board.

Q42 How does JTAG test a PCB trace between Chip A and Chip B?

Answer:
1. JTAG commands Chip A's output pin to drive a Logic 1 (using the BSC).
2. JTAG commands Chip B's input pin to capture the state of the PCB trace (using its BSC).
3. The captured value is shifted out via TDO. If a 1 is read, the solder joint and PCB trace are perfect. If 0 is read, there is a physical open circuit or short to ground on the motherboard.

Q43 What is the TAP Controller?

Answer: A 16-state Finite State Machine inside the JTAG block. It is navigated solely by toggling the TMS pin on the rising edge of TCK. It controls whether JTAG is shifting an Instruction or shifting Data.

Q44 Tricky How do you force a JTAG TAP controller into the Reset state if you don't know what state it is currently in?

Answer: The JTAG state machine is mathematically designed so that holding the TMS pin HIGH (1) for 5 consecutive TCK clock cycles guarantees the state machine will arrive at the Test-Logic-Reset state, no matter where it started. This makes the TRST pin optional.

Q45 Explain the BYPASS instruction in JTAG.

Answer: When testing a board with 10 chips connected in a JTAG daisy-chain, you may only want to test Chip 5. The BYPASS instruction routes TDI directly to TDO through a 1-bit shift register for the other 9 chips. This bypasses their massive boundary scan chains, drastically speeding up the shifting process for the target chip.

Q46 Contrast the EXTEST and INTEST JTAG instructions.

Answer:
• EXTEST: Boundary scan cells face outward. Used to test external PCB connectivity between chips.
• INTEST: Boundary scan cells face inward. Used to apply static stimulus to the internal core logic of the chip while isolated from the PCB.

Q47 What is the IDCODE instruction?

Answer: It reads a hardcoded 32-bit register providing the Manufacturer ID, Part Number, and Silicon Revision. Automated test equipment reads this first to verify the correct chip was soldered onto the board before applying test patterns.

Q48 Can JTAG be used for anything other than manufacturing tests?

Answer: Yes! JTAG has evolved into the universal back-door into a chip. It is heavily used by firmware engineers for On-Chip Debugging (e.g., OpenOCD/GDB to halt the CPU, step through C code, and read registers) and for programming Flash memories and FPGAs.

Q49 What is a BSDL file?

Answer: Boundary Scan Description Language. It is a file provided by the chip vendor that describes the exact length and order of the Boundary Scan chain inside the chip. PCB test tools use this file to understand how to shift bits into the JTAG port to manipulate specific physical pins.

Q50 The Final Wrap-Up: How are JTAG, ATPG, and BIST connected?

Answer: Modern SoCs use JTAG (IEEE 1149.1/1500) as the master gateway. A test engineer connects the JTAG cable, which toggles the TAP controller. The TAP controller issues instructions to switch the chip into Scan Mode (allowing ATE to run ATPG patterns), or it issues an instruction to fire off the MBIST/LBIST engines internally, subsequently reading out the pass/fail signatures via TDO. JTAG orchestrates the entire DFT ecosystem.

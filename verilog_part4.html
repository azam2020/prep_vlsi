Chapter 2: Verilog HDL — Part 4 (Q151 to Q200)

Timing Delays, System Tasks, Testbenches, and Whiteboard Debugging

11. Timing Delays: Inertial vs. Transport

Q151 What is Inertial Delay in Verilog, and what hardware does it model?

Answer: Inertial delay models the minimum amount of energy (time duration) a signal must sustain to change the output of a logic gate. It acts as a Glitch Filter. Any pulse narrower than the inertial delay is ignored and not propagated to the output.

Q152 How do you code Inertial Delay in Verilog?

Answer: By using a delay on a continuous assignment. 

assign #5 y = a & b;
If `a & b` glitches high for only 3ns, `y` will never change. The pulse must be ≥ 5ns to pass through.

Q153 What is Transport Delay in Verilog, and what hardware does it model?

Answer: Transport delay models the time it takes for a signal to travel down a long physical wire (flight time). It does NOT filter glitches. Every single pulse, no matter how tiny, is propagated to the output exactly as it appeared, just shifted in time.

Q154 Tricky How do you code Transport Delay in Verilog?

Answer: By using Intra-assignment delay with a non-blocking operator inside a procedural block. 

always @(a or b) begin
    y <= #5 (a & b);
end

Concept: Because it is non-blocking (`<=`), the simulator schedules the event for 5 time units in the future without blocking the thread. Multiple tiny pulses will schedule multiple updates, propagating all glitches perfectly.
Q155 What is Inter-assignment Delay? Provide syntax.

Answer: The delay is placed on the left side of the variable. It completely pauses the execution of the procedural block for the specified time. 

#5 a = b; // Wait 5ns, then read 'b' and assign to 'a'.

Q156 What is Intra-assignment Delay? Provide syntax.

Answer: The delay is placed on the right side of the assignment operator. It reads the RHS immediately, then waits, then updates the LHS. 

a = #5 b; // Read 'b' NOW, wait 5ns, assign the old cached value of 'b' to 'a'.

Q157 Explain the difference between @ and wait in testbenches.

Answer:
• @ (posedge clk): Is Edge-Sensitive. It pauses execution until it sees a transition on the signal.
• wait (en == 1): Is Level-Sensitive. It pauses execution until the condition is true. If `en` is ALREADY 1 when the line executes, it does not pause at all and proceeds immediately.

Q158 How do you declare and trigger a Named Event in Verilog?

Answer: You declare an event, trigger it using ->, and wait for it using @. 

event data_ready;
...
-> data_ready;     // Trigger the event
...
@(data_ready);     // Wait for the event in another block

Q159 Tricky What happens if a `wait (a == 1)` statement is reached at the exact same simulation time step that `a` transitions to 1?

Answer: This creates a race condition in the event queue depending on execution order! If `a` is assigned 1 in the Active region before the `wait` evaluates, it passes immediately. If the `wait` evaluates first, it will stall until `a` is evaluated. (Always use `@` for syncing concurrent events securely).

Q160 How do you model Clock Jitter in a Verilog testbench?

Answer: By adding a randomized delay factor to the clock toggling using `$urandom_range`. 

always begin
    #(10 + $urandom_range(0, 2) - 1) clk = ~clk; // Jitter between 9ns and 11ns
end

12. System Tasks & Testbench Architecture

Q161 What is the difference between force/release and assign/deassign system tasks?

Answer:
• assign / deassign: Procedural continuous assignments. They override standard assignments but can ONLY be applied to `reg` data types.
• force / release: Absolute override. They can be applied to BOTH `wire` and `reg` data types. (Crucial for testbenches forcing internal DUT wire nodes).

Q162 What happens to a `reg` after you execute a release command on it?

Answer: The `reg` retains the value that was forced onto it until the next procedural assignment explicitly updates it. (A `wire`, however, immediately reverts to the value being driven by its continuous drivers).

Q163 What is the difference between $finish and $stop?

Answer:
• $stop: Suspends the simulation and puts the EDA tool into interactive debugging mode (CLI prompt).
• $finish: Completely terminates the simulation and exits the simulator back to the host OS command line.

Q164 How do you generate a random 32-bit number in Verilog?

Answer: Use $random. To ensure it is purely positive (unsigned), use {$random} or the SystemVerilog specific $urandom.

Q165 Why is providing a seed to $random(seed) critical for verification?

Answer: Without a specific seed, the simulator generates the exact same sequence of "random" numbers every time you run the simulation. Passing a seed (often derived from system time or command line) ensures different stimulus patterns per run, while allowing you to reuse a failing seed to exactly recreate and debug a failure.

Q166 What do $time, $stime, and $realtime return?

Answer:
• $time: Returns the current simulation time as a 64-bit integer.
• $stime: Returns the time as a 32-bit integer (truncates upper bits).
• $realtime: Returns the time as a 64-bit Real (floating point) number, accounting for fractional timescale precision.

Q167 How do you format $display to print a variable in Hex, Binary, and Decimal?
$display("Hex: %h, Bin: %b, Dec: %d", val, val, val);
Q168 What does the %m format specifier do in $display?

Answer: It prints the Hierarchical Name (the full path) of the module instance where the `$display` statement executed. Essential for debugging which instantiation of a sub-module threw an error.

Q169 How do you pass arguments from the OS command line into your Verilog simulation?

Answer: Using Plusargs! ($test$plusargs and $value$plusargs). 

// Run command: vsim tb_top +DEBUG_MODE +SEED=42
if ($test$plusargs("DEBUG_MODE")) $display("Debug ON");
if ($value$plusargs("SEED=%d", seed_val)) $display("Seed is %d", seed_val);

Q170 How do you dump waveforms in Verilog for viewing in GTKWave or Verdi?

Answer: You must create a VCD (Value Change Dump) file in the testbench. 

initial begin
    $dumpfile("waves.vcd");
    $dumpvars(0, tb_top); // '0' means dump all levels of hierarchy under tb_top
end

Q171 How do you write data out to a text file during simulation?
integer file_id;
initial begin
    file_id = $fopen("output_log.txt", "w");
    $fdisplay(file_id, "Simulation Started at %t", $time);
    $fclose(file_id);
end
Q172 Tricky How do you create a Timeout Watchdog in a Verilog testbench?

Answer: Use a parallel `initial` block. If the main testbench hangs in an infinite loop, this watchdog ensures the simulator doesn't run forever and consume server resources. 

initial begin
    #1000000;
    $display("FATAL: Simulation Timeout!");
    $finish;
end

Q173 What is $timeformat used for?

Answer: It formats how the `%t` specifier prints time in `$display`.
Syntax: $timeformat(unit, precision, suffix, min_width);
E.g., $timeformat(-9, 2, " ns", 10); prints time in nanoseconds with 2 decimal places.

Q174 How can you check for Setup and Hold timing violations directly in Verilog (without STA tools)?

Answer: Using system tasks inside a specify ... endspecify block. 

specify
    $setup(data, posedge clk, 2.0); // 2ns setup check
    $hold(posedge clk, data, 1.0);  // 1ns hold check
endspecify
The simulator will automatically print a timing violation warning if the `data` changes within these windows.

Q175 What is a Glitch in a Verilog testbench, and why does reading inputs on the active clock edge cause them?

Answer: If a testbench drives `a = 1` on exactly the `posedge clk`, the RTL sampling `a` on that exact same `posedge clk` suffers a race condition. It might sample 0, or it might sample 1. Solution: Testbenches should always drive stimulus on the negative edge of the clock (or use non-blocking assignments) so data is perfectly stable when the DUT samples it on the positive edge.

13. Whiteboard Debugging & Traps

Q176 Identify the Bug What is wrong with this clock divider logic? 
always @(posedge clk) begin
    clk_out = ~clk_out;
end

Answer: It uses a blocking assignment (=) in a sequential edge-triggered block. In hardware, `clk_out` acts as a clock for other modules. If you use `=`, any module sampling `clk_out` in the same Active region might suffer a race condition. It MUST be clk_out <= ~clk_out;.

Q177 Identify the Bug What is wrong with this assignment? 
wire a;
always @(*) begin
    a = b & c;
end

Answer: You cannot assign a wire inside an always block! It will fail compilation. a must be declared as a reg, or the logic must be rewritten as assign a = b & c;.

Q178 Identify the Bug What is wrong with this MUX? 
always @(sel or a or b) begin
    if (sel == 1'bx) y = 1'b0;
    else if (sel) y = a;
    else y = b;
end

Answer: Checking for 1'bx using the logical equality operator == always returns X (False in if-statements). To check for `X`, you MUST use the case equality operator ===. (e.g., if (sel === 1'bx)).

Q179 Identify the Bug Find the simulation hang. 
initial begin
    clk = 0;
    forever clk = ~clk;
end

Answer: The forever loop has no time delay! It will loop infinitely at time `t=0` (Delta cycle lock-up), freezing the simulation. It must be: forever #5 clk = ~clk;.

Q180 Identify the Bug Why won't this reset block work reliably? 
always @(posedge clk or negedge rst_n) begin
    if (rst_n == 0) q <= 0;
    else q <= d;
end

Answer: If `rst_n` transitions to `X` or `Z` (very common at simulation time 0 before drivers are active), `rst_n == 0` evaluates to False (`X`). The Flip-Flop misses the reset! It should be if (!rst_n) which safely catches 0 (and handles initial states better), or explicitly if (rst_n === 1'b0).

Q181 Identify the Bug Why is this testbench stimulus bad practice? 
initial begin
    @(posedge clk);
    data = 1;
    @(posedge clk);
    data = 0;
end

Answer: Using a blocking assignment exactly on the clock edge creates a race condition with the DUT which is also sampling on the posedge.
Fix: Use non-blocking data <= 1; to schedule the drive in the NBA region (after the DUT samples in Active), or drive on the negedge: @(negedge clk) data = 1;.

Q182 What happens if two `initial` blocks conflict? 
initial a = 1;
initial a = 0;

Answer: This is a simulation race condition. The value of `a` at time 0 will be completely arbitrary depending on which block the simulator decides to evaluate last. (EDA tools process them in an undefined order).

Q183 Identify the Bug What's wrong with this synthesis code? 
always @(posedge clk) begin
    y <= a;
    y <= b;
end

Answer: y is assigned multiple times in the same clock cycle. In Verilog, the last non-blocking assignment textually wins. So `y` will always take the value of `b`. `a` is completely ignored and synthesized away.

Q184 What is the output of `$display` here? 
reg [3:0] a;
initial begin
    a = 4'b1111;
    $display("Value is %d", a + 1'b1);
end

Answer: The output is 0. `a` is 15. Adding 1 causes integer overflow (16, which is 5-bits `1_0000`). Because the expression width is bounded by the max width of the operands (4 bits), it truncates to `0000`.

Q185 Whiteboard How do you initialize a 2D memory array in a single line of Verilog?

Answer: You CANNOT initialize an entire unpacked array in a single assignment (like `mem = 0;`). You must use a `for` loop, or use `$readmemh` to load it from a file. 

integer i;
initial begin
    for(i=0; i<256; i=i+1) mem[i] = 8'h00;
end

Q186 Can you instantiate a module inside an always block?

Answer: NO. Modules are static physical hardware boundaries. They can only be instantiated at the module top-level (structural level). You cannot dynamically instantiate hardware based on behavioral events.

Q187 What is the difference between `reg` and `logic`?

Answer: `logic` is a SystemVerilog enhancement. It solves the Verilog `wire` vs `reg` confusion. You can use `logic` for both continuous assignments (`assign logic_var = ...`) and procedural blocks (`always @(*) logic_var = ...`), heavily simplifying RTL coding.

Q188 Why must parameters be evaluated at compile time?

Answer: Parameters define physical hardware limits (like bus widths or the number of instantiated modules). Physical silicon cannot change its bus width after it has been manufactured, so these values must be resolved before synthesis begins.

Q189 What is a hierarchical reference in Verilog?

Answer: Accessing variables deeply buried in sub-modules using dot notation. E.g., `tb_top.dut.fsm_block.current_state`. Excellent for testbench verification, but STRICTLY BANNED in RTL synthesis because it breaks physical module isolation.

Q190 What happens if you connect a 4-bit output port to a 2-bit wire?

Answer: Verilog quietly truncates the upper 2 bits of the output port, issuing only a compiler warning. The lower 2 bits connect to the wire. (Another reason to always check synthesis warnings!).

Q191 How do you force synthesis to keep a register that it thinks is useless?

Answer: Use the (* preserve = "true" *) or (* dont_touch = "true" *) attribute right before the `reg` declaration.

Q192 Can an assign statement have a sensitivity list?

Answer: No. Continuous assignments are implicitly sensitive to all signals on the right-hand side. The concept of an explicit sensitivity list only applies to procedural `always` blocks.

Q193 Is `always @(*)` sensitive to memory arrays?

Answer: Yes, but typically only to the specific index being accessed. If `array[index]` is read, changes to `index` trigger the block. Changes to the array data at that index also trigger it.

Q194 What is the default base for numbers in Verilog if not specified? (e.g., `a = 15;`)

Answer: Decimal. A plain `15` is treated as a 32-bit signed decimal number.

Q195 How do you write a binary number with a "don't care" bit?

Answer: Using `?` or `x`. Example: `4'b10?1` (Matches 1001 or 1011 in a `casex` statement).

Q196 What is the difference between `case`, `casex`, and `casez`?

Answer:
• `case`: Exact match required (treats X/Z as literal X/Z).
• `casez`: Treats `Z` (and `?`) as don't cares.
• `casex`: Treats `X` AND `Z` (and `?`) as don't cares. (Avoid in RTL to prevent silent X-propagation masking).

Q197 How do you define a MACRO with an argument?
`define MAX(a, b) ((a) > (b) ? (a) : (b))
// Used as: result = `MAX(x, y);
Q198 What happens if you forget to declare a module's inputs/outputs inside the port list?

Answer: By default (Verilog-95 legacy), undeclared ports default to 1-bit `wire`. Modern Verilog-2001 ANSI style requires explicit declaration `module my_mod(input wire clk, output reg out);` to prevent silent bugs.

Q199 What is the difference between `<` and `<= ` logic operators?

Answer: `<` is strictly Less Than. `<=` serves a double purpose in Verilog: in an expression (`if (a <= b)`) it means Less Than or Equal. In an assignment (`a <= b;`) it means Non-Blocking assignment.

Q200 The Final Test: What does this code do? 
always @(posedge clk) begin
    a <= a ^ b;
    b <= a ^ b;
    a <= a ^ b;
end

Answer: It fails. It does NOT swap A and B.

The Ultimate Trap: In software, XOR swapping works because updates are sequential. In a Non-Blocking Verilog block, all RHS equations are evaluated simultaneously using the OLD values.

RHS evaluation:
Line 1 schedules `a` to become `old_a ^ old_b`.
Line 2 schedules `b` to become `old_a ^ old_b`.
Line 3 schedules `a` to become `old_a ^ old_b` (overwriting Line 1).

Result: Both `a` and `b` receive the identical XOR result. The data is destroyed. To swap in Verilog, just use `a <= b; b <= a;`!

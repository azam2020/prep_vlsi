Chapter 6: Memories, SoC & CDC — Part 2 (Q51 to Q100)

SoC Architecture, AMBA Protocols (APB, AHB, AXI), DMA, and Arbitration

4. SoC Architecture & AMBA Overview

Q51 What is an SoC (System on Chip)?

Answer: An SoC integrates all components of a computer or electronic system onto a single silicon substrate. It typically includes a CPU (microprocessor), memory blocks (ROM, RAM), hardware accelerators (GPU, NPU), timers, and peripheral interfaces (USB, SPI, UART), all connected via an on-chip communication fabric.

Q52 What is the AMBA standard?

Answer: Advanced Microcontroller Bus Architecture. Introduced by ARM, it is an open-standard, on-chip interconnect specification for the connection and management of functional blocks in SoC designs. It dictates how masters (CPUs/DMAs) talk to slaves (Memories/Peripherals).

Q53 List the 3 most common AMBA protocols used in modern SoCs and their target applications.

Answer:
1. APB (Advanced Peripheral Bus): Low bandwidth, low power, simple non-pipelined. Used for slow peripherals (UART, Timers, I2C).
2. AHB (Advanced High-performance Bus): High bandwidth, pipelined. Used for shared memory and standard system modules.
3. AXI (Advanced eXtensible Interface): Ultra-high performance, high frequency, parallel channels, out-of-order execution. Used for CPU-to-Memory and high-speed data streams (PCIe, Video).

Q54 What is the difference between a Bus Master and a Bus Slave?

Answer:
• Master (Initiator): The component that initiates the read or write transaction by providing address and control signals (e.g., CPU, DMA controller).
• Slave (Target): The component that responds to the transaction requested by the master. It cannot initiate transfers (e.g., Memory, APB peripherals).

Q55 What is an Interconnect Fabric (or Interconnect Matrix)?

Answer: A central routing hub that manages connections between multiple Masters and multiple Slaves. Instead of a single shared physical wire (which bottlenecks), modern fabrics use Crossbar Switches to allow simultaneous non-blocking transactions (e.g., Master 1 talks to Slave A while Master 2 talks to Slave B).

5. APB (Advanced Peripheral Bus)

Q56 What are the defining characteristics of APB?

Answer: It is unpipelined, meaning it cannot start a new transfer until the current one finishes. It consumes exactly 2 clock cycles per standard transfer. It lacks burst capabilities and is strictly intended for simple register programming.

Q57 Name the key control signals of the APB protocol.

Answer:
• PSEL: Select signal (indicates the specific slave is chosen).
• PENABLE: Enable signal (marks the active access phase).
• PWRITE: Direction (High for Write, Low for Read).
• PREADY: Wait state signal driven by the slave (Slave extends the transfer if it needs more time).

Q58 Explain the 2-cycle state machine of a standard APB Write transfer.

Answer:
1. Setup Phase (Cycle 1): The master drives Address (`PADDR`), Data (`PWDATA`), Direction (`PWRITE=1`), and asserts `PSEL`. `PENABLE` remains 0.
2. Access Phase (Cycle 2): The master asserts `PENABLE=1`. The slave samples the data on this clock edge. If `PREADY=1`, the transfer completes. The master drops `PENABLE` and `PSEL` on the next edge.

Q59 Tricky What happens if a slave drives `PREADY=0` during the Access Phase?

Answer: The master must freeze its state. It must hold the Address, Data, `PSEL`, and `PENABLE` perfectly stable for as many clock cycles as `PREADY` remains low. The transfer only completes on the clock edge where `PENABLE=1` AND `PREADY=1` simultaneously.

Q60 What is `PSLVERR`?

Answer: APB Slave Error. Driven by the slave during the Access Phase (when `PREADY=1`) to indicate the transfer failed (e.g., the master tried to write to a read-only register or an invalid address).

6. AHB (Advanced High-performance Bus)

Q61 What makes AHB faster than APB?

Answer: AHB is Pipelined. The Address phase of the current transfer heavily overlaps with the Data phase of the previous transfer. This allows AHB to achieve 1 data transfer per clock cycle during a burst, doubling the throughput of APB.

Q62 Describe the two pipelined phases of an AHB transfer.

Answer:
1. Address Phase: Master drives Address and Control signals (`HTRANS`, `HSIZE`, `HWRITE`). Lasts exactly 1 cycle.
2. Data Phase: Master drives/samples Data (`HWDATA`/`HRDATA`). The slave responds with `HREADY`. Can be extended by driving `HREADY=0`.

Q63 What does the `HTRANS` signal do, and what are its 4 states?

Answer: It tells the slave what kind of transfer the master is performing.
• 00 (IDLE): Master is doing nothing. Slave ignores data.
• 01 (BUSY): Master is in the middle of a burst but needs a cycle to think. Slave ignores data.
• 10 (NONSEQ): Non-sequential. The first transfer of a burst, or a single isolated transfer.
• 11 (SEQ): Sequential. The continuing transfers in a burst (address is related to the previous NONSEQ transfer).

Q64 Tricky What is the difference between Master `HREADY` (Wait State) and Slave `HREADY`?

Answer: A slave uses `HREADY` to pause the Data Phase if it needs more time. A master uses `HTRANS = BUSY` to pause the Address Phase of a burst. The pipeline dictates that if a slave drives `HREADY=0`, it stalls the entire pipeline, forcing the master to freeze the address of the next pending transfer as well.

Q65 What is an AHB "Split" or "Retry" response?

Answer: If a slow slave knows it will take 100 cycles to fetch data, holding `HREADY=0` locks up the entire bus, starving other masters.
• SPLIT/RETRY: The slave tells the arbiter "I need time, disconnect this master and let someone else use the bus. I will signal when I'm ready." This dramatically improves overall system bus utilization.

7. AXI (Advanced eXtensible Interface)

The 5 Independent AXI Channels

Notice how Address and Data are physically separate buses in AXI.

Q66 Name the 5 completely independent channels in the AXI protocol.

Answer:
1. AR (Read Address): Master sends read address.
2. R (Read Data): Slave sends data back to master.
3. AW (Write Address): Master sends write address.
4. W (Write Data): Master sends write data.
5. B (Write Response): Slave acknowledges the write completion.

Q67 What is the fundamental Handshake mechanism used on ALL 5 AXI channels?

Answer: VALID and READY.
The source drives data/address and asserts VALID when the information is good. The destination asserts READY when it is able to accept it. The information is officially transferred ONLY on the clock edge where VALID == 1 AND READY == 1.

Q68 Can a Master wait for `READY` to be high before asserting `VALID`?

Answer: NO. AXI protocol strictly dictates that a source must assert VALID completely independent of READY. Waiting for READY before driving VALID causes a combinatorial deadlock (deadly embrace) if the destination is simultaneously waiting for VALID before asserting READY.

Q69 How does AXI achieve higher bandwidth than AHB using its channels?

Answer: In AHB, Address and Data share the same pipeline constraint. In AXI, the Address and Data channels are completely separated. A master can blast 10 write addresses (AW) down the channel immediately without waiting, and then pump the actual write data (W) later. This is called Outstanding Transactions.

Q70 What is Out-of-Order Execution in AXI?

Answer: A master can issue a read to slow memory (Transaction ID=1) and a read to fast cache (Transaction ID=2). The slave can return the data for ID=2 before ID=1. The master uses the Transaction IDs to reassemble the data correctly. This prevents slow transactions from blocking fast ones.

Q71 What are the 3 AXI Burst Types (AxBURST)?

Answer:
1. FIXED (0b00): Address remains the same for every transfer. (Used for loading data into a single FIFO).
2. INCR (0b01): Incrementing. Address increments by the transfer size for each beat. (Normal sequential memory access).
3. WRAP (0b10): Wrapping. Address increments but wraps back to a lower boundary if it crosses a memory boundary. (Used exclusively by CPUs fetching cache lines).

Q72 In AXI, how is the total amount of data in a single burst calculated?

Answer: It is the number of transfers (Beats) multiplied by the size of each transfer.
Total Bytes = (AxLEN + 1) * (2 ^ AxSIZE).

Q73 Numerical If AWLEN = 8'h0F and AWSIZE = 3'b010, how many bytes are transferred in the burst?

Answer:
• Beats = `AWLEN + 1` = 15 + 1 = 16 beats.
• Bytes per Beat = `2 ^ AWSIZE` = $2^2$ = 4 bytes (32-bits).
• Total Burst = 16 beats * 4 bytes/beat = 64 bytes.

Q74 What does the WLAST signal do?

Answer: It is driven by the master on the Write Data (W) channel to explicitly indicate that the current data beat is the final piece of data in the entire burst. (The slave uses RLAST on the read channel).

Q75 What is WSTRB (Write Strobe) in AXI?

Answer: It allows sparse or byte-aligned writing. There is one strobe bit for every 8 bits (byte) of the data bus. If a master sends 32-bits of data but only sets `WSTRB[0] = 1` and `WSTRB[3:1] = 0`, the slave will only overwrite the lowest byte in memory, preserving the upper 3 bytes.

Q76 What is the difference between AXI3 and AXI4 regarding Burst Length?

Answer: AXI3 supports a maximum of 16 beats per burst (AxLEN is 4 bits). AXI4 expanded this to support up to 256 beats per burst for INCR transfers (AxLEN is 8 bits), drastically improving DMA bulk copy performance.

Q77 What feature did AXI4 remove from AXI3?

Answer: Write Interleaving. In AXI3, a master could send Write Data for Transaction ID=1, then pause, send a beat of data for Transaction ID=2, then resume ID=1. It made slave logic incredibly complex to reassemble. AXI4 banned Write Interleaving; all data for a single burst must be sent continuously in order.

Q78 What is AXI-Lite?

Answer: A simplified subset of the AXI protocol designed for simple control registers (replacing APB). It strips out bursts (all transactions are exactly 1 beat), removes IDs, and removes out-of-order execution, leaving just the 5 basic handshake channels.

Q79 Tricky Can a Slave send the Write Response (B channel) before receiving the Write Data (W channel)?

Answer: NO. AXI ordering rules explicitly state that the Slave must wait until the `WLAST` signal (final data beat) has been accepted (VALID & READY) before it is legally allowed to assert `BVALID` on the response channel.

Q80 Explain AXI Response Codes (`BRESP` and `RRESP`).

Answer: 2-bit indicators of transfer success.
• OKAY (00): Success.
• EXOKAY (01): Exclusive Access Success (used for atomic semaphores/locks).
• SLVERR (10): Slave Error. Reached the slave, but the slave rejected it (e.g., read-only).
• DECERR (11): Decode Error. The address doesn't exist anywhere in the interconnect matrix.

8. DMA, Arbitration & System Integration

Q81 What is a DMA (Direct Memory Access) controller?

Answer: A specialized hardware block that handles massive bulk data transfers between memory and peripherals (e.g., RAM to Network MAC) without using the CPU. The CPU simply configures the DMA with a Source Address, Dest Address, and Size, then goes to sleep or does other work. The DMA issues an interrupt when finished.

Q82 How does Scatter-Gather DMA differ from Block DMA?

Answer: Standard Block DMA transfers one continuous block of memory. Scatter-Gather DMA reads a "Linked List" of descriptors from memory. It finishes transferring Block A, then automatically reads the next descriptor to find Block B and transfers it, without needing the CPU to wake up and reprogram it.

Q83 Why do SoCs require Bus Arbitration?

Answer: Because multiple Masters (e.g., CPU, DMA, GPU) are attached to the Interconnect. If both the CPU and DMA try to read from the DDR RAM at the exact same clock cycle, the arbiter decides who gets access to the slave and who is forced to wait.

Q84 Explain Fixed Priority Arbitration.

Answer: Masters are ranked. Master 1 always wins over Master 2.
Flaw: Starvation. If Master 1 demands constant bus access (like a greedy GPU), Master 2 (like an audio interface) will never get access and audio will drop out.

Q85 Explain Round-Robin Arbitration.

Answer: Access is granted sequentially in a circle (Master 1 $\rightarrow$ 2 $\rightarrow$ 3 $\rightarrow$ 1). If a master doesn't need the bus, it skips its turn. This guarantees 100% fairness and completely eliminates starvation, making it the industry standard for general-purpose buses.

Q86 What is a Network-on-Chip (NoC)?

Answer: In extremely large SoCs (like an Apple M-series), traditional Crossbar interconnects become too huge and unroutable. A NoC treats the silicon like an internet network. Data is packetized into "flits" and routed through packet-switched routers distributed across the chip to their destination.

Q87 How do you prevent Deadlock in a NoC or complex Interconnect?

Answer: Deadlock happens when Master A waits for Master B, and Master B waits for Master A. It is prevented by mathematically ensuring routing algorithms are "Cycle-Free" (e.g., X-Y routing) or by allocating dedicated Virtual Channels (separate buffers) for different traffic classes.

Q88 What is an Address Decoder in an SoC?

Answer: A combinational logic block inside the Interconnect. When a Master sends a 32-bit address (e.g., `0x4000_0000`), the decoder checks an internal memory map, determines that this address belongs to "UART0", and asserts the Select signal to route the transaction to the UART slave.

Q89 What is a "Bridge" module (e.g., AXI2APB Bridge)?

Answer: A protocol translator. High-speed CPUs speak AXI. Slow peripherals speak APB. The bridge is an AXI Slave on one side and an APB Master on the other. It takes a fast AXI burst, breaks it down into individual APB 2-cycle transfers, and returns the response back to the AXI domain.

Q90 What happens if an AXI Master writes to a Memory address that is not mapped to any slave?

Answer: The Address Decoder catches the unmapped address. Instead of locking up the bus waiting for a slave that doesn't exist, the interconnect fabric contains a "Default Slave" (or Error Slave). The Default Slave immediately responds with a DECERR (Decode Error) to properly terminate the transaction.

Q91 What is Memory Mapped I/O (MMIO)?

Answer: CPUs interact with hardware peripherals (like turning on an LED or reading a sensor) by reading and writing to specific physical memory addresses. The CPU doesn't know it's an LED; it just executes a standard Store instruction to `0x8000_1004`, and the interconnect routes it to the GPIO block instead of RAM.

Q92 Tricky What is an Atomic Access (Exclusive Access)?

Answer: In multi-core systems, two CPUs might try to update the same memory location simultaneously, causing data corruption. An atomic access (using AXI `AxLOCK` signals) ensures that a CPU can Read, Modify, and Write back to a location without any other Master being allowed to access that address in between.

Q93 Why do high-performance SoCs use multiple clock domains?

Answer: Power and timing isolation. A CPU might run at 3GHz to maximize performance, but a USB controller only needs 480MHz, and an RTC (Real-Time Clock) needs 32kHz. Splitting domains saves massive dynamic power and isolates critical timing closure to small regions.

Q94 What is Cache Coherency?

Answer: If a multi-core SoC has an L1 cache for CPU 0 and an L1 cache for CPU 1, they might both hold a copy of memory address `0xA000`. If CPU 0 modifies its cache, CPU 1's cache becomes "stale" (incorrect). Hardware coherency protocols (like MESI or ARM's ACE protocol) ensure all caches instantly snoop and update/invalidate stale data.

Q95 What is QoS (Quality of Service) in an AXI Interconnect?

Answer: AxQOS signals allow a Master to tag a transaction's priority. A Display Controller fetching video pixels gets high QoS so the screen doesn't tear, while a background DMA copy gets low QoS. The arbiters prioritize routing based on these tags.

Q96 How do you verify an AXI protocol interface in testbenches?

Answer: Using VIPs (Verification IP). Engineers don't write manual AXI testbenches from scratch. They license AXI VIPs (from Cadence/Synopsys) which contain thousands of pre-written assertions (SVA) that rigorously monitor the bus and instantly flag protocol violations (e.g., "VALID fell before READY was asserted").

Q97 What is AXI Narrow Transfer?

Answer: When a Master generates a transfer size (AxSIZE) that is narrower than the actual physical data bus width. The Master must use the WSTRB signals to indicate which specific byte lanes contain the valid data on the wide bus.

Q98 What happens if an APB master writes to a slave, but the slave never asserts PREADY?

Answer: The APB bus suffers a total dead-lock. The master freezes in the Access Phase infinitely. Robust SoC architectures prevent this by instituting Watchdog Timers inside the Interconnect that automatically terminate the transfer and return an Error if the slave takes longer than X cycles.

Q99 In AXI, can a Write Address channel (AW) and Write Data channel (W) arrive simultaneously?

Answer: Yes. The AXI protocol explicitly states there is no fixed temporal relationship between AW and W. The data can arrive simultaneously with the address, after the address, or even before the address (though sending data before the address is discouraged for performance reasons in AXI4).

Q100 The Final Test: What is the main architectural difference between AXI and APB?

Answer: APB is a shared-bus, non-pipelined, 2-cycle protocol where Address and Data are inherently tied together in time. AXI is a channel-based, decoupled, burst-oriented protocol where Address, Data, and Response travel on separate physical channels, enabling outstanding, overlapping, and out-of-order execution.

Chapter 6: Memories, SoC & CDC — Part 1 (Q1 to Q50)

SRAM vs DRAM, Clock Domain Crossing (CDC), and Asynchronous FIFOs

1. Memory Basics: SRAM & DRAM

Q1 What is the fundamental difference between SRAM and DRAM?

Answer:
• SRAM (Static RAM): Uses bistable latching circuitry (cross-coupled inverters) to store each bit. Fast, consumes more area (6 transistors/cell), and requires no refresh. Used for CPU Cache.
• DRAM (Dynamic RAM): Stores bits as charge in a tiny capacitor. Slow, extremely dense (1 transistor + 1 capacitor/cell), and leaks charge over time, requiring continuous periodic refresh cycles. Used for Main System Memory.

Q2 Describe the architecture of a standard 6T SRAM cell.

Answer: It consists of exactly 6 transistors:
1. Two cross-coupled CMOS inverters (4 transistors total: 2 Pull-Up PMOS, 2 Pull-Down NMOS) that hold the logical state regeneratively.
2. Two NMOS Access Transistors (Pass Transistors) connected to the Word Line (WL) that control access to the Bit Line (BL) and Bit Line Bar ($\overline{BL}$) for reading and writing.

6T SRAM Cell Architecture
Q3 Explain the Read Operation in a 6T SRAM cell.

Answer:
1. Precharge: Both Bit Line ($BL$) and Bit Line Bar ($\overline{BL}$) are precharged to $V_{DD}$.
2. Enable: The Word Line (WL) is driven High, turning ON both NMOS access transistors.
3. Discharge: Depending on the stored state, one of the cross-coupled inverters will pull one of the bit lines down slightly toward GND.
4. Sense: A Sense Amplifier detects the tiny voltage differential ($\Delta V$) between $BL$ and $\overline{BL}$ and instantly amplifies it to a full CMOS logic level.

Q4 Why do we use Sense Amplifiers during an SRAM read instead of just letting the cell discharge the bitline to 0V?

Answer: Speed. The Bit Lines are massively long wires shared across thousands of cells, possessing enormous parasitic capacitance. The tiny transistors inside a single SRAM cell are far too weak to discharge that entire capacitance to 0V quickly. The Sense Amp detects a drop of just ~100mV and aggressively drives the output, saving immense time.

Q5 Explain the Write Operation in a 6T SRAM cell.

Answer:
1. The Write Driver forces $BL$ to the desired value (e.g., $V_{DD}$) and $\overline{BL}$ to its complement ($0V$).
2. The Word Line (WL) is driven High, turning ON the access transistors.
3. The strong Write Drivers overpower the tiny cross-coupled inverters inside the cell, flipping their state to match the bit lines.
4. WL is turned off, and the inverters latch the new state.

Q6 Tricky What is the conflict between "Read Stability" and "Write Ability" in SRAM sizing?

Answer:
• Read Stability: During a read, the access NMOS must be weaker than the internal pull-down NMOS, so the cell doesn't accidentally flip its own state when connected to the precharged bit lines.
• Write Ability: During a write, the access NMOS must be stronger than the internal pull-up PMOS, so the external write drivers can successfully overpower the cell and flip it.
This physical sizing conflict defines the SRAM Cell Ratio (CR) and Pull-Up Ratio (PR).

Q7 What is Static Noise Margin (SNM) in SRAM?

Answer: SNM is the maximum DC noise voltage that can be applied to the internal storage nodes of the SRAM cell without flipping its state. It is graphically represented by the side of the largest square that can fit inside the "Butterfly Curve" formed by plotting the VTCs of the two cross-coupled inverters against each other.

Q8 Why does DRAM require a "Destructive Read"?

Answer: A DRAM cell stores charge on a microscopic capacitor. To read it, the access transistor connects this capacitor to the bitline. The charge physically spills out onto the bitline to be read by the sense amp, destroying the voltage level in the cell. The memory controller must immediately write the data back into the cell after reading.

Q9 Why must DRAM be refreshed?

Answer: Because the storage capacitor isn't perfect; it leaks charge into the substrate through the access transistor's subthreshold leakage and junction leakage. If not refreshed (read and written back) every few milliseconds (e.g., 64ms), the stored logic 1 will decay into a logic 0.

Q10 What is a Multi-port RAM (e.g., Dual-Port RAM)?

Answer: A memory block that has multiple independent address, data, and control buses. A Dual-Port RAM allows two completely independent operations (e.g., two reads, two writes, or one read and one write) to occur at different memory addresses at the exact same time.

Q11 What happens if both ports of a Dual-Port RAM attempt to Write to the exact same address simultaneously?

Answer: This is an Address Collision (Memory Hazard). The memory contents at that address become corrupted (`X` state). The SoC architecture must implement arbitration logic or lock mechanisms outside the RAM to prevent this.

Q12 What is a CAM (Content Addressable Memory)?

Answer: Standard RAM takes an Address and returns the Data. CAM does the exact opposite: It takes a Data Word as input, searches its entire memory simultaneously in one clock cycle, and returns the Address where that data is stored. It is used heavily in network routers for high-speed IP routing lookups.

Q13 How does Flash Memory store data without power?

Answer: Using a Floating Gate Transistor. A secondary polysilicon gate is completely encased in insulating oxide, isolated from the rest of the circuit. High voltage is used to force electrons through the oxide via Fowler-Nordheim tunneling. Once trapped in the floating gate, they cannot escape, permanently altering the transistor's threshold voltage ($V_{TH}$) to represent a 0 or 1.

Q14 Explain the difference between Endianness (Big-Endian vs. Little-Endian) in memory.

Answer: Endianness describes how multi-byte data words are stored in byte-addressable memory.
• Little-Endian: The Least Significant Byte (LSB) is stored at the lowest memory address. (Used by Intel x86).
• Big-Endian: The Most Significant Byte (MSB) is stored at the lowest memory address. (Used by ARM in network mode).

Q15 What is Memory Interleaving (Banking)?

Answer: A technique to increase memory bandwidth. Instead of one large monolithic RAM, memory is split into multiple independent banks. Sequential addresses are placed in different banks. The CPU can issue a read to Bank 0, and while Bank 0 is fetching, it can immediately issue the next read to Bank 1, hiding the memory latency.

2. Clock Domain Crossing (CDC) Basics

Q16 What constitutes a Clock Domain Crossing (CDC)?

Answer: A CDC occurs whenever a signal generated by a flip-flop in one clock domain (Launch Clock) is sampled by a flip-flop operating in a completely different, asynchronous clock domain (Capture Clock).

Q17 Why are CDC paths inherently dangerous?

Answer: Because the two clocks have no fixed phase relationship, the launch data will inevitably transition right as the capture clock edge arrives. This violates the Setup and Hold time requirements of the destination flip-flop, forcing it into a state of Metastability.

Q18 What is Metastability?

Answer: A state where a flip-flop's output hovers at an intermediate voltage level between Logic 0 and Logic 1 for an unpredictable amount of time before finally resolving to a random state. If this metastable value propagates to downstream logic, the entire state machine can crash.

Q19 Write the equation for MTBF (Mean Time Between Failures) regarding metastability.
$MTBF = \frac{e^{t_r / \tau}}{T_0 \cdot f_{clk} \cdot f_{data}}$

Where $t_r$ is the resolution time provided to the flip-flop to settle, $\tau$ is a technology constant, $f_{clk}$ is the destination clock frequency, and $f_{data}$ is the toggle rate of the incoming data.

Q20 How do we increase the MTBF to prevent system crashes?

Answer: The only variable in the MTBF equation we can effectively control is $t_r$ (Resolution Time). By using a 2-Flip-Flop Synchronizer, we grant the first flip-flop an entire clock cycle to resolve its metastability before the second flip-flop samples it, pushing the MTBF from fractions of a second to millions of years.

Standard 2-FF Synchronizer
Q21 Tricky Does a 2-FF Synchronizer fix Setup and Hold violations?

Answer: NO. A synchronizer does not magically make the signal meet setup/hold times. The setup/hold times will be violated, and the first flip-flop will go metastable. The 2-FF synchronizer merely acts as a quarantine zone, containing the metastability and preventing it from spreading to the rest of the logic.

Q22 What is the Golden Rule of the 2-FF Synchronizer?

Answer: There must be strictly ZERO combinational logic between the output of the first synchronizing flip-flop and the input of the second. Combinational logic adds delay, which steals from the resolution time ($t_r$), catastrophically destroying the MTBF.

Q23 Why can't we use a 2-FF Synchronizer to cross a multi-bit Data Bus (e.g., a 32-bit address)?

Answer: Data Incoherency. Because clock edges and wire delays vary slightly, some bits of the 32-bit bus might get captured on cycle 1, while other bits go metastable and get captured on cycle 2. The receiving domain reconstructs a fractured, Frankenstein data word that never existed in the source domain. 2-FF synchronizers are strictly for single-bit control signals.

Q24 How do you safely cross a Multi-Bit Bus across clock domains?

Answer:
1. Asynchronous FIFO: (The standard method for streaming data).
2. MUX Recirculation (Handshaking): Hold the data bus perfectly stable, pass a 1-bit "Data Valid" flag through a 2-FF synchronizer, and use that synchronized flag to toggle a MUX to capture the multi-bit data in the receiving domain.

Q25 Define the "Fast to Slow" CDC problem.

Answer: If CLK_A is much faster than CLK_B, a 1-cycle pulse in domain A might be so narrow that domain B completely misses it (the pulse arrives and disappears between B's clock edges). Data is permanently lost.

Q26 How do you solve the Fast-to-Slow pulse transfer problem?

Answer:
1. Pulse Stretching: Domain A must hold the signal high for at least $1.5 \times T_{clk\_B}$ to guarantee domain B catches it.
2. Toggle Synchronizer: Domain A converts the pulse into a level toggle (T-Flip Flop). Domain B synchronizes the level, then uses an edge-detector to convert it back into a pulse.

Q27 What is a Toggle Synchronizer? Write the receiving edge-detector logic.

Answer: Domain A toggles a signal. Domain B passes it through a 2-FF synchronizer (`sync_ff2`), then delays it by one more cycle (`sync_ff3`). An edge is detected when the two delayed versions differ. 

wire pulse_detected = sync_ff2 ^ sync_ff3; // XOR detects any edge

Q28 Define the "Slow to Fast" CDC problem.

Answer: If CLK_A is much slower than CLK_B, a 1-cycle pulse in domain A spans many cycles in domain B. Domain B will sample it multiple times, interpreting a single event as multiple consecutive events.

Q29 How do you solve the Slow-to-Fast pulse transfer problem?

Answer: In Domain B, after the 2-FF synchronizer, add a third flip-flop and an AND gate to create a Rising Edge Detector. 

wire pulse_out = sync_ff2 & ~sync_ff3;
This ensures the long level signal only generates exactly one pulse in the fast domain.

Q30 What is "Reconvergence" in CDC?

Answer: A fatal design error where two related signals from Domain A are passed through two separate 2-FF synchronizers, and then their outputs are combined (reconverged) in Domain B. Because synchronizers can delay signals unpredictably by 1 or 2 cycles due to metastability, the signals lose their alignment, causing invalid logic states in Domain B.

3. Asynchronous FIFOs

Q31 What is an Asynchronous FIFO?

Answer: A First-In-First-Out memory queue where data is written using one clock (Write Clock) and read using a completely different, asynchronous clock (Read Clock). It is the industry standard mechanism for passing massive amounts of data safely between clock domains.

Q32 What are the 4 main components of an Async FIFO?

Answer:
1. Dual-Port RAM: To hold the data (no clock-domain crossing occurs in the RAM itself).
2. Write Pointer & Logic: Tracks where to write, synchronized to Write Clock.
3. Read Pointer & Logic: Tracks where to read, synchronized to Read Clock.
4. Synchronizers: 2-FF synchronizers to pass the Read Pointer to the Write domain, and the Write Pointer to the Read domain.

Q33 Why MUST we use Gray Code for the FIFO Pointers?

Answer: Standard Binary counters change multiple bits simultaneously (e.g., $011 \rightarrow 100$ changes 3 bits). If passed through a 2-FF synchronizer, skew could cause the receiving domain to capture an invalid intermediate state (like $111$). Gray code guarantees only 1 bit changes per transition, so the receiving domain either catches the old value perfectly or the new value perfectly—never garbage.

Q34 Write the Verilog logic to convert Binary to Gray code.
wire [N:0] gray = binary ^ (binary >> 1);
Q35 Why do FIFO pointers need an extra MSB (N+1 bits) compared to the memory address width (N bits)?

Answer: The extra MSB is used to distinguish between the "Full" and "Empty" conditions. When the Read and Write pointers wrap around the memory, their lower N bits will match. The extra MSB tracks how many times they have wrapped.

Q36 What is the condition for FIFO Empty?

Answer: The FIFO is exactly empty when the Read Pointer completely catches up to the Write Pointer.
Logic: `assign empty = (rd_ptr_gray == wr_ptr_gray_sync);`
(Evaluated entirely within the Read Clock domain).

Q37 Tricky What is the condition for FIFO Full using Gray Code pointers?

Answer: The FIFO is full when the Write Pointer wraps around and catches the Read Pointer from behind. In Gray code, this means the lower N-1 bits match exactly, but the top two MSBs are inverted.
Logic: 

assign full = (wr_ptr_gray == {~rd_ptr_gray_sync[N:N-1], rd_ptr_gray_sync[N-2:0]});
(Evaluated entirely within the Write Clock domain).

Q38 Why is the "Full" flag generated in the Write Domain, and the "Empty" flag generated in the Read Domain?

Answer: Safety. The Write logic must stop writing instantly when full to prevent overwriting. It evaluates Full using its own fast, native Write pointer, compared against a delayed (synchronized) Read pointer. Same logic applies for Empty in the Read domain. This avoids cycle delays in stopping bad operations.

Q39 What does it mean that Async FIFO flags are "Pessimistic"?

Answer:
• Pessimistic Full: Because the Read pointer takes 2 cycles to synchronize into the Write domain, the Write logic thinks the FIFO is full even if the Read logic just popped data. The FIFO stops writing slightly early.
• Pessimistic Empty: The Read logic thinks the FIFO is empty because the latest Write pointer hasn't synced over yet, so it stops reading slightly early.
This pessimism slightly reduces bandwidth but guarantees 100% safety against data loss.

Q40 Are synchronizers needed on the actual Data Bus of the Async FIFO?

Answer: NO. Data is written directly into the Dual-Port RAM. The RAM is a static memory. By the time the Read pointer updates, synchronizes across domains, and tells the Read logic the data is ready, many clock cycles have passed. The data at that address is completely stable, avoiding all CDC issues.

Q41 What is the "Almost Full" and "Almost Empty" flag?

Answer: Flags that assert a few cycles *before* absolute Full/Empty. They are used in high-latency bus architectures (like AXI). If the upstream bus controller takes 3 cycles to halt data transmission after receiving a stop signal, "Almost Full" must trigger 3 slots early to prevent overflow.

The Famous FIFO Depth Calculations
Q42 Write the fundamental formula for calculating required FIFO Depth.

The goal is to calculate how much data accumulates in the FIFO during a worst-case continuous burst write, before the slower read side can pull it out.

$Depth = Burst\_Size - \left( \frac{Burst\_Size}{F_{write}} \right) \times F_{read}$

Note: This assumes 1 data word per clock cycle.

Q43 Numerical A transmitter writes at 100 MHz in bursts of 80 words. The receiver reads at 50 MHz. What is the minimum FIFO depth to prevent overflow?

Answer:
1. Time taken to write the burst: $T = 80 / 100\text{MHz} = 800\text{ns}$.
2. How many words can be read in that 800ns window? $Read = 800\text{ns} \times 50\text{MHz} = 40\text{ words}$.
3. Unread words accumulated: $80 - 40 = \mathbf{40\text{ words}}$.
The FIFO depth must be at least 40.

Q44 Numerical Write freq = 80 MHz, Read freq = 50 MHz. Burst size = 120. Receiver has a 1-cycle idle penalty every 4 words. Find FIFO Depth.

Answer:
1. Time to write 120 words = $120 / 80\text{M} = 1500\text{ns}$.
2. The receiver effectively reads 4 words every 5 clock cycles. Effective Read frequency = $50\text{MHz} \times (4/5) = 40\text{MHz}$.
3. Words read during burst = $1500\text{ns} \times 40\text{MHz} = 60\text{ words}$.
4. Min Depth = $120 - 60 = \mathbf{60\text{ words}}$.

Q45 Why should FIFO depth always be forced to a power of 2 (e.g., 64 instead of 60)?

Answer: To make pointer wrapping free. If a FIFO depth is $2^N$, the N-bit pointer naturally wraps from maximum back to 0 perfectly. If you use a non-power-of-2 depth (like 60), the counter must explicitly reset at 59. This breaks the single-bit-flip rule of standard Gray code, causing catastrophic CDC failures.

Q46 Tricky What if you absolutely MUST use a non-power-of-2 FIFO depth?

Answer: You must use an Even-Symmetric Gray Code (or "Truncated Gray Code"). You throw away an equal number of states from the top and bottom of the standard Gray code sequence. Because it remains symmetric around the center, the wrap-around jump still only flips exactly one bit.

Q47 What is a "First-Word Fall-Through" (FWFT) FIFO?

Answer: In a standard FIFO, you assert `read_en` and the data appears on the next clock cycle. In a FWFT FIFO, the very first word written immediately propagates through to the output data pins without waiting for a `read_en`. The `read_en` acts as an acknowledge to discard the current word and reveal the next one. Crucial for AXI valid/ready handshaking.

Q48 What is "Watermarking" in a FIFO?

Answer: Programmable thresholds. Instead of fixed Almost_Full logic, a CPU configures a register (the watermark) to trigger an interrupt when the FIFO hits 75% full, allowing the software driver to initiate a DMA transfer before overflow occurs.

Q49 How do you safely reset an Async FIFO?

Answer: An async FIFO spans two clock domains, meaning it needs two reset synchronizers. The global asynchronous reset must be synchronized into the Write Clock domain to reset the write pointers, and separately synchronized into the Read Clock domain to reset the read pointers, preventing race conditions during wake-up.

Q50 The Final Test: Does a Synchronous FIFO use Gray code pointers?

Answer: NO. In a Synchronous FIFO, the read and write logic share the exact same clock. There are no clock domain crossings, no metastability risks, and no synchronizers. Therefore, standard Binary counters are used, making empty/full math simple subtraction. Gray code is exclusively required for Asynchronous CDC.

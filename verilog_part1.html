Chapter 2: Verilog HDL — Part 1 (Q1 to Q50)

Simulation Engine, Stratified Event Queue, Data Types, Operators & Operators Mechanics

1. Verilog Event Queue & Simulation Engine

Q1 What is the Verilog Stratified Event Queue, and why is it important for RTL engineers?

Answer: The Verilog Stratified Event Queue is an algorithmic queue used by simulators (e.g., VCS, ModelSim) to order and execute concurrent events happening at the exact same simulation time step. It is crucial because physical hardware operates simultaneously, but software simulators must execute sequentially on a single-threaded CPU. The event queue guarantees deterministic behavior across different EDA tools when RTL is coded correctly.

Q2 List the main regions of the Verilog-2001 Stratified Event Queue in order of execution.

Answer: At any given simulation time step, events execute in these primary regions:

  1. Active Region: Evaluates RHS of all assignments, executes blocking assignments (=), continuous assignments (assign), and $display statements. Evaluates RHS of non-blocking assignments (<=).
  2. Inactive Region: Executes events scheduled with a #0 delay.
  3. Non-Blocking Assign (NBA) Update Region: Updates the LHS variables of all non-blocking assignments evaluated in the Active region.
  4. Monitor / Postponed Region: Executes $monitor, $strobe, and updates VCD waveform dumps after all updates are stable.
Q3 Tricky What happens when you execute #0 a = b;? Which event queue region does it trigger, and why is it banned in commercial RTL guidelines?

Answer: #0 forces the execution of a = b to move from the current Active Region to the Inactive Region of the current time step. It is strictly banned in production RTL (Qualcomm/AMD guidelines) because it introduces artificial execution ordering, creates non-deterministic simulation race conditions, and cannot be synthesized into physical silicon hardware.

Trap / Secret Used: Interviewers ask this to test if you rely on hacky simulation tricks. Always state that #0 does not defer execution to the next clock edge or time step—it deferments to the Inactive Region of the same time step.
Q4 Tricky Analyze these two concurrent blocks: 
always @(posedge clk) a <= b;
always @(posedge clk) b <= a;
Why is there NO race condition? Trace using the Event Queue.

Answer: There is no race condition; values of a and b are reliably swapped.
1. Active Region: The RHS of both blocks are read simultaneously. The current value of b is evaluated for a, and current a is evaluated for b.
2. NBA Region: The LHS variables a and b are updated simultaneously with the values cached during the Active Region.

Concept Used: Non-blocking assignments (<=) enforce a strict 2-step process: Evaluate RHS in Active Region → Update LHS in NBA Region. This separation guarantees race-free swaps.
Q5 Tricky Analyze these two concurrent blocks: 
always @(posedge clk) a = b;
always @(posedge clk) b = a;
What is the outcome in simulation? Is it deterministic?

Answer: This creates a Simulation Race Condition. The behavior is non-deterministic and tool-dependent. Both blocks execute in the Active Region. If Block 1 executes first, a gets b's value, and then Block 2 executes, giving b the new value of a (both end up with b's original value). If Block 2 executes first, both end up with a's original value.

Trap Used: Blocking assignments (=) evaluate AND update immediately inside the Active Region. Never use blocking assignments across multiple edge-triggered blocks!
Q6 Compare $display, $write, $strobe, and $monitor in terms of how they execute in the Event Queue.

Answer:

  • $display: Executes in the Active Region immediately when encountered, adds a newline character.
  • $write: Identical to $display (Active Region), but does not add a automatic newline.
  • $strobe: Postpones execution to the Postponed/Monitor Region at the very end of the time step after all updates are stable.
  • $monitor: Automatically executes in the Postponed Region whenever any of its arguments change value. Only one $monitor can be active at a time.
Q7 Tricky Given the snippet below, what will $display print vs what will $strobe print? 
initial begin
    a = 10;
    a <= 20;
    $display("Display: a = %d", a);
    $strobe("Strobe: a = %d", a);
end

Output:
Display: a = 10
Strobe: a = 20

Concept Used: $display runs in the Active Region before the NBA Region updates a to 20. $strobe runs in the Postponed Region after the NBA update completes.
Q8 What is a simulation delta cycle (delta delay)?

Answer: A delta cycle is a zero-time-duration execution step inside the simulator. It allows the simulator to evaluate causality (cause-and-effect chain) across combination logic or event regions without advancing the primary time counter (e.g., time remains at 10ns while multiple delta iterations execute).

Q9 What is the default initial state of an uninitialized wire vs an uninitialized reg at time t=0?

Answer:
• Uninitialized wire defaults to Z (High Impedance / Floating).
• Uninitialized reg defaults to X (Unknown / Uninitialized state).

Q10 Can a wire have multiple drivers in Verilog? What value does it assume if driven by both 1 and 0?

Answer: Yes, a wire (net type) supports multiple drivers. If one driver pushes logic 1 and another pushes logic 0 to the same wire simultaneously, signal contention occurs, and the wire resolves to X (Unknown/Contention).

2. Data Types, Variables & Memory Arrays

Q11 What is the fundamental difference between wire and reg from a synthesis vs simulation perspective?

Answer:
• Simulation Perspective: wire is a net that cannot hold a value (must be continuously driven). reg is a variable object that holds its assigned value until updated inside a procedural block.
• Synthesis Perspective: Both can represent physical wires or gates! A reg inside an always @(*) block synthesizes into a pure combinational wire/gate, NOT a hardware register.

Q12 Explain the 4-state logic system in Verilog and the physical meaning of each value.

Answer:
• 0: Logic Low / Ground (GND).
• 1: Logic High / Supply (VDD).
• X: Unknown / Uninitialized / Driver Contention.
• Z: High Impedance / Tri-stated / Disconnected wire.

Q13 Tricky What is the output of the addition 4'b1010 + 4'b00x1?

Answer: 4'bxxxx (or 4'bxx11 depending on simulator, but structurally 4'bxxxx because 'X' propagates through bitwise addition).

Concept Used: X-Propagation. Any arithmetic operation (+, -, *, /) containing a single 'X' or 'Z' bit causes the entire mathematical result bit-vector to contaminate to 'X'.
Q14 Tricky What is the difference between == and === operators? Is === synthesizable?

Answer:
• == (Logical Equality): Returns X if either operand contains 'X' or 'Z'.
• === (Case Equality): Performs an exact 4-state bitwise comparison including 'X' and 'Z'. Returns strictly 1 or 0.
• Synthesis: === is NON-SYNTHESIZABLE. It is strictly used in testbenches.

Trap Used: Attempting to use === in RTL will cause synthesis tools (e.g., Synopsys Design Compiler) to throw an error or ignore the check, creating a simulation-synthesis mismatch!
Q15 What is the output of:
1) (4'b10xz == 4'b10xz)
2) (4'b10xz === 4'b10xz)

Answer:
1) Output is 1'bx (because == cannot resolve X/Z comparison).
2) Output is 1'b1 (because === sees identical 4-state literal matches).

Q16 What are Packed vs Unpacked arrays in Verilog? Provide code syntax.

Answer:
• Packed Array (Vector): Declared before the variable name. Represents a continuous contiguous bus.
• Unpacked Array (Memory): Declared after the variable name. Represents a collection of registers/memories.

wire [7:0] packed_bus;       // 8-bit packed vector
reg [7:0] memory [0:1023];  // Unpacked array: 1024 depth array of 8-bit words
Q17 How are Packed vs Unpacked arrays laid out in simulator memory?

Answer: Packed arrays are guaranteed to be stored as a single contiguous set of bits in memory (efficient bit-slicing). Unpacked arrays store elements in separate memory words/slots, allowing independent element indexing.

Q18 Can you select a bit-slice of an element in an unpacked array directly in Verilog-2001? Write syntax.

Answer: Yes. Syntax: array_name[element_index][bit_high:bit_low]
Example: wire lower_nibble = memory[42][3:0]; (Extracts lower 4 bits of memory address 42).

Q19 Write Verilog code to model a 2 Kilobyte RAM block where each word is 16 bits wide.

Answer: 2 KB = 2048 Bytes = 1024 words of 16-bits (2 Bytes per word).

reg [15:0] ram_block [0:1023]; // 1024 depth x 16-bit width = 2048 Bytes
Q20 Tricky What is Indexed Part-Select (+: and -:)? Why is it necessary?

Answer: Standard part-select (e.g., bus[i+3 : i]) is illegal in Verilog when i is a variable because the slice width must be fixed at compile time. Indexed part-select solves this by allowing variable base index with a constant width.

Syntax: data[base_expr +: width] or data[base_expr -: width]

Example: data[i +: 4] starting at index i=8 selects 4 bits upwards: data[11:8]. Width is fixed to 4.
Q21 What is the difference between integer, reg, time, and real data types in Verilog?

Answer:
• reg: Variable length vector (default 1-bit), 4-state. Synthesizable.
• integer: Signed 32-bit vector, 4-state. Synthesizable (typically used for loop indices).
• time: Unsigned 64-bit vector, 4-state. Used in testbenches for $time.
• real: 64-bit IEEE floating-point scalar, 2-state. NON-SYNTHESIZABLE.

Q22 Tricky What happens if you assign a negative number to an unsigned reg [3:0]? E.g., reg [3:0] a = -4;

Answer: Verilog automatically converts the negative integer to its 2's complement equivalent bit pattern. -4 in 4-bit 2's complement is 4'b1100 (12 in unsigned decimal).

Q23 What is the default signedness of expressions in Verilog? How do you force a reg or wire to be signed?

Answer: By default, all wire and reg declarations are unsigned. You force them to be signed using the signed keyword: 

reg signed [7:0] s_data;
wire signed [15:0] s_result;

Q24 Tricky What happens if you perform an operation mixing a signed signal and an unsigned signal? E.g., signed_a + unsigned_b.

Answer: If ANY operand in an expression is unsigned, Verilog automatically converts ALL operands in the expression to unsigned! The signed signal is treated as unsigned, leading to silent calculation bugs.

Trap / Concept: This is a major Qualcomm/AMD interview question. To preserve signed evaluation, explicitly cast the unsigned operand using $signed(unsigned_b)!
Q25 What do system functions $signed() and $unsigned() do?

Answer: They are type-casting functions. $signed(x) returns the same bit pattern as x, but forces the Verilog expression evaluator to treat it as a signed 2's complement number.

3. Operators, Bit-Extensions, and Shift Logic

Q26 What is a Reduction Operator? List all reduction operators in Verilog.

Answer: A reduction operator takes a single multi-bit vector operand, applies a bitwise operation across all its bits, and reduces it to a single 1-bit result.
Operators: & (AND), ~& (NAND), | (OR), ~| (NOR), ^ (XOR), ~^ or ^~ (XNOR).

Q27 How do you generate an odd-parity bit for an 8-bit bus data[7:0] in 1 line of Verilog?

Answer: wire parity = ^data; (Applies reduction XOR across all 8 bits).

Q28 Difference between Bitwise AND (&) and Logical AND (&&). Give outputs for 4'b1010 & 4'b1100 vs 4'b1010 && 4'b1100.

Answer:
• 4'b1010 & 4'b1100 = 4'b1000 (Bit-by-bit AND operation, 4-bit output).
• 4'b1010 && 4'b1100 = 1'b1 (Evaluates non-zero operands as True, returns 1-bit True/False boolean).

Q29 Explain Concatenation {} and Replication {N{}} operators with code examples.

Answer:
• Concatenation joins vectors together: wire [7:0] bus = {a[3:0], b[3:0]};
• Replication repeats a vector N times: wire [7:0] bus = {4{2'b10}}; // Outputs 8'b10101010

Q30 Tricky Write a 1-line expression to sign-extend a 4-bit signed signal in[3:0] into an 8-bit signal out[7:0] using replication.

Answer: assign out = {{4{in[3]}}, in[3:0]};

Concept Used: The MSB in[3] is the sign bit. Replicating it 4 times at the head of the vector preserves 2's complement sign extension!
Q31 Difference between Logical Shift (<<, >>) and Arithmetic Shift (<<<, >>>).

Answer:
• Logical Right Shift (>>): Always fills freed MSB positions with zeros.
• Arithmetic Right Shift (>>>): If the operand is signed, it replicates the MSB (sign bit) to preserve sign. If unsigned, it behaves like a logical shift.

Q32 Tricky What is the value of res in this code? 
reg [3:0] val = 4'b1000; // Unsigned!
wire [3:0] res = val >>> 2;

Answer: res = 4'b0010 (NOT 4'b1110!).

Trap Used: Even though the operator used is arithmetic shift >>>, the variable val was NOT declared with the signed keyword! Verilog defaults to zero-fill unless declared as reg signed [3:0].
Q33 Explain Bit-Width Expansion during addition. How do you prevent overflow in wire [7:0] a, b;?

Answer: Adding two N-bit numbers produces an (N+1)-bit maximum sum. To prevent overflow, size the LHS destination bus to 9 bits and evaluate width: 

wire [7:0] a, b;
wire [8:0] sum = a + b; // Verilog automatically pads operands to 9-bits before adding

Q34 What is the output of 4'b1010 ^~ 4'b0101? What operator is this?

Answer: Output is 4'b0000. The operator ^~ or ~^ is the bitwise XNOR operator (returns 1 when bits match, 0 when they differ).

Q35 What is the Conditional / Ternary Operator ? :? Can it be nested?

Answer: It evaluates sel ? in1 : in0 to implement a 2:1 MUX combinational logic. Yes, it can be freely nested to implement priority encoders or multi-input MUXes.

Q36 Tricky What does a ternary expression synthesize to if sel evaluates to X in simulation? E.g., out = (1'bx) ? a : b;

Answer: In simulation, if select is X, the ternary operator performs bitwise comparison: bits where a and b match are passed through; bits where they differ output X. In hardware, a 2:1 MUX will physically select either A or B, demonstrating a simulation-synthesis abstraction difference!

Q37 How does Verilog evaluate expression bit-widths? What is a Self-Determining vs Context-Determined expression?

Answer:
• Self-Determining: Bit-width depends strictly on the expression itself regardless of LHS (e.g., shifts, logical comparisons).
• Context-Determined: Bit-width is padded to match the maximum width of the LHS destination variable or maximum operand width in the equation before computing.

Q38 What is the purpose of built-in gate primitives like nand, nor, bufif1, notif0?

Answer: They allow structural gate-level modeling directly without needing a module definition. E.g., nand g1 (out, in1, in2); (Note: Output pin is always listed first!).

Q39 Why is module port instantiation by name preferred over instantiation by position?

Answer: Instantiation by position (sub_mod m1 (a, b, c);) is highly error-prone if port order changes in the sub-module. Instantiation by name (sub_mod m1 (.clk(a), .data(b));) is self-documenting and order-independent.

Q40 How do you model a Tri-state Buffer in Verilog using continuous assignment?

Answer: 

assign data_bus = (oe) ? tx_data : 1'bz;

4. Directives, Parameters & Code Generation

Q41 What is the difference between `define, parameter, and localparam?

Answer:
• `define: Global macro pre-processor directive. Accessible across ALL files in compile order.
• parameter: Local to a specific module scope. **Can be overridden** during top-level instantiation.
• localparam: Local to a module scope. **CANNOT be overridden** from top-level (used for dependent constants like state encodings).

Q42 Why is `default_nettype none mandatory in commercial Verilog coding standards?

Answer: By default, Verilog automatically infers an undeclared signal name as a 1-bit wire. If you misspell a bus name (e.g., data_buss), Verilog silently creates a 1-bit wire, causing catastrophic silent net disconnection bugs. `default_nettype none disables auto-wire creation and forces compiler errors for undeclared variables.

Q43 What is a generate block in Verilog? When must you use it?

Answer: A generate block dynamically generates hardware modules, assignments, or procedural blocks at compile time based on parameters. Used for repeating structures (e.g., instantiating 32 bit-slice ALUs) or conditional parameter-based hardware selection.

Q44 What is a genvar variable? Can it be modified at runtime during simulation?

Answer: genvar is a special loop variable used exclusively inside generate-for loops. It exists strictly at elaboration/compile time and cannot be modified at runtime during simulation.

Q45 Write a Verilog generate block to instantiate an array of N XOR gates.

Answer: 

parameter N = 8;
genvar i;
generate
    for (i = 0; i < N; i = i + 1) begin : xor_loop
        xor g_inst (out[i], a[i], b[i]);
    end
endgenerate

Q46 Tricky What is the difference between a generate-for loop and a standard for loop inside an always block?

Answer:
• generate-for: Duplicates physical hardware blocks/modules at compile-time.
• always block for-loop: Represents behavioral iteration inside a single procedural block. Unrolls combinational logic, does NOT instantiate multiple hardware modules!

Q47 How do you automatically calculate address bus width for a parameter DEPTH using system function $clog2?

Answer: 

parameter DEPTH = 256;
localparam ADDR_WIDTH = $clog2(DEPTH); // Calculates log2(256) = 8 bits

Q48 What happens if you assign a 5-bit signal to a 3-bit signal in Verilog? E.g., wire [2:0] out = 5'b11010;

Answer: Verilog automatically **truncates the upper bits** without warning! out receives lower 3 bits: 3'b010. (Major source of silent bus width mismatch bugs).

Q49 What happens if you assign a 3-bit signal to a 5-bit signal in Verilog? E.g., wire [4:0] out = 3'b101;

Answer: Verilog automatically **zero-extends** the upper bits. out becomes 5'b00101. If the source was declared signed, it sign-extends instead.

Q50 Tricky Explain the compiler difference between `include "file.v" and compiling files together in a filelist (-f files.f).

Answer: `include literally copy-pastes the code of file.v into the current file pre-processor stream before compilation. A filelist tells the EDA tool to compile separate files into the library. Re-defining modules inside an `included file causes duplicate module definition errors.
